# 기능 아이디어 보관

착수하지 않은 아이디어를 기록만 해 두는 문서다. 실제로 진행할 때는 `docs/PROJECT.md` 규칙에 따라 `docs/items/<항목>.md`를 만들고, 여기서는 해당 줄을 지운다.

출처: 2026-09-22 Cursor(composer-2.5) 에이전트에게 저장소를 읽게 한 뒤 받은 제안 15개 중, 바로 구현한 '소' 규모 5개와 상세설계서를 쓴 디렉터리 비교(`docs/items/directory-compare.md`)를 제외한 나머지.

각 항목은 **가치 / 구현 스케치 / 규모 / 주의점** 순서다.

---

## 중 (1~3일)

### Git 작업 트리 상태 오버레이
- **가치**: 사용자가 개발자다. `git status`를 치지 않아도 수정·추적 안 됨·충돌 파일을 목록에서 바로 알 수 있으면 매일 쓰는 폴더에서 체감이 크다.
- **스케치**: `.git`이 있는 상위 폴더를 찾아 `git status --porcelain`(또는 LibGit2Sharp)을 백그라운드로 읽는 `GitStatusService`(신규). `FileSystemItem`에 `GitStatus` enum을 붙이고 `FolderBrowser` 목록의 파일명 색 또는 별도 컬럼으로 표시. `FolderBrowser.RefreshItems`와 `FileSystemWatcher` 갱신에 연동.
- **규모**: 중.
- **주의점**: Git for Windows PATH 의존, 대형 저장소에서 전체 status 비용(폴더 단위 `git status -- <path>`로 좁힐 것), WSL 경로 매핑. `IgnoreRuleSet`과 표시 정책을 맞출 것(ignore된 파일은 상태도 숨김).

### Monaco 기반 Diff 뷰어 탭
- **가치**: 코드 리뷰·설정 diff·로그 비교를 브라우저나 외부 도구 없이 앱 안에서 side-by-side로 본다.
- **스케치**: `Viewers/DiffViewer`(`IFileViewer`) 또는 `MonacoViewer`의 diff 모드. `Viewers/Resources/`에 Monaco diff editor HTML. `MainWindow` 문서 탭 컨텍스트 메뉴에 "다른 파일과 비교…", 반대편 패널의 같은 상대 경로와 비교. 디렉터리 비교 기능의 파일 단위 후속 동작으로도 쓰인다.
- **규모**: 중.
- **주의점**: WebView2 리소스 크기, 대용량 diff 성능. `ViewerConfigService` 확장자 매핑과는 별개의 "도구 탭"으로 두고, `OpenViewerTab`의 단일 파일 중복 방지 로직과 구분되는 `ContentId` 규칙(`diff|a|b`)이 필요.

### 폴더 크기 분석 (디스크 사용량의 하위 확장)
- **가치**: 드라이브 단위 사용량은 이미 있다. "어느 하위 폴더가 50GB를 먹는지"는 개발 디스크 정리에 필수.
- **스케치**: `DiskUsageService.GetFolderSizes(root, maxDepth, ct)` 추가. `FolderBrowser` 컨텍스트 메뉴 "이 폴더 크기 분석" → `LayoutDocument` 탭에 트리 + 가로바(`FractionToStarConverter` 재사용).
- **규모**: 중.
- **주의점**: `SearchService.EnumerateFiles`의 접근 거부·reparse point 순환 처리 재사용. 수십만 파일 스캔 시 진행률·취소 필수.

### 정규식·일련번호 배치 이름 변경
- **가치**: `report_v1.txt → report_v2.txt` 같은 다중 파일 이름 변경은 Explorer로는 못 한다.
- **스케치**: `FileOperationService.RenameBatch` + 미리보기 그리드가 있는 다이얼로그(`PromptWindow` 확장). `MainWindow`의 `Rename`/`F2` 흐름에서 다중 선택이면 배치 다이얼로그로 분기.
- **규모**: 중.
- **주의점**: 이름 충돌·예약 파일명(`CON` 등)·경로 길이. 트리뷰 폴더 고정 잠금(`tree-view-folder-pin-lock`)의 rename 허용 정책과 충돌하지 않게.

### 로그 tail 뷰어 (`IFileViewer` 확장)
- **가치**: 빌드·서버 로그를 `tail -f`처럼 앱 안에서 본다.
- **스케치**: `TextViewer` 확장 또는 `LogViewer` 신규. `FileSystemWatcher` + 주기적 tail 읽기, 자동 스크롤, 대용량은 끝 N KB만 유지. `ViewerConfigService`에 `.log` 기본 매핑 추가 검토.
- **규모**: 중.
- **주의점**: `MarkdownViewer`의 외부 변경 감시 패턴 재사용 가능. 로테이션된 로그 파일 핸들, UTF-16 LE 인코딩.

### 작업 프로필 (레이아웃 + 즐겨찾기 + 시작 폴더 묶음)
- **가치**: 프로젝트마다 도킹 배치·즐겨찾기·열어 둘 폴더가 다르다. 이름 붙인 프로필로 한 번에 전환.
- **스케치**: `WorkspaceProfileService`(신규, `profiles.xml`)가 `DockLayoutService.Save`·`SessionStateService.Save`·`FavoritesService` 스냅샷을 이름별로 저장. `MainWindow` 메뉴 "프로필 전환".
- **규모**: 중.
- **주의점**: `panel-locks.xml`·`session.xml`·`dock-layout.xml` 버전 호환. 전환 시 열린 뷰어(미저장 변경 확인)·콘솔 세션 정리 UX. "기본 도킹 배치로 초기화"와 역할 구분.

## 대 (1주 이상)

### 단방향 폴더 동기화 (미러/백업)
- **가치**: 디렉터리 비교의 다음 단계. 배포·백업·테스트 fixture 동기화.
- **스케치**: `SyncService`(신규)가 비교 결과를 바탕으로 `FileOperationService`로 복사·삭제(선택)를 배치 실행. dry-run 미리보기 다이얼로그.
- **규모**: 대.
- **주의점**: 삭제 방향 실수·ACL·긴 경로·취소·부분 실패. 대량 파일 작업은 별도 로그와 실행 취소 스택이 짝이 맞다(`docs/keyboard-shortcuts.md` §6의 `Ctrl+Z` 제안과 연결).

### 중복 파일 찾기 (내용 해시)
- **가치**: 디스크 정리, 빌드 아티팩트 중복 제거.
- **스케치**: `DuplicateFinderPanel`(`LayoutDocument`) + `SearchService`식 순회 + 크기 사전 필터 + SHA-256(백그라운드). 결과에서 삭제·탐색기로 이동.
- **규모**: 대.
- **주의점**: TB급 스캔 시간·네트워크 드라이브. 순회·링크 내성은 `SearchServiceTests` 패턴으로 단위 테스트 가능.

### 검색 엔진 선택 (내장 스캔 + ripgrep 옵션)
- **가치**: 대형 저장소에서 순수 C# 줄 스캔은 느릴 수 있다.
- **스케치**: `SearchService`에 `ISearchBackend` 추상화. 설정에서 `rg.exe` 경로와 폴백 선택.
- **규모**: 대.
- **주의점**: rg 미설치 PC, stdout 파싱·인코딩, 정규식/와일드카드 의미 차이. CI 테스트는 내장 백엔드만.

## 후속 후보 (구현한 '소' 기능에서 갈라져 나온 것)

- **콘솔 프로필별 마지막 작업 폴더 기억**: Cursor 제안의 절반. 현재 콘솔은 항상 활성 폴더에서 시작하는 것이 설계라 충돌한다. 넣는다면 설정 창에 "새 콘솔은 프로필의 마지막 작업 폴더에서 시작" 옵트인 체크박스와 `console-settings.xml`의 프로필별 경로가 필요하다.
- **뷰어 닫기 시 "저장 / 저장 안 함 / 취소" 3버튼**: 지금은 "닫을까요? 예/아니요"만 있다. 저장은 WebView2 안의 편집기 내용을 비동기로 받아와야 해서 `Closing`(동기 취소) 흐름과 맞추려면 "일단 취소 → 저장 완료 후 자동 닫기" 방식이 필요하다.
- **ignore 필터 기본값·영구 저장**: 현재 패널 단위 토글이고 재시작하면 꺼진다. 개발자 사용자에게는 기본 켜짐이 더 편할 수 있으나, 파일이 안 보이는 놀라움이 있어 설정 항목으로 두는 것이 안전하다.
- **`.folderssignore` 전역 규칙 파일**: `%LOCALAPPDATA%\Folderss\ignore-patterns.txt` 같은 사용자 전역 규칙. `IgnoreRuleSet.LoadFor`에 소스 하나 추가하면 된다.
- **검색 결과 필터의 평면 보기**: 지금은 결과가 있는 하위 폴더로 내려가는 방식이다. 하위 폴더의 결과 파일을 상대 경로 컬럼과 함께 한 목록에 펼쳐 보이는 모드는 `FolderBrowser`의 항목 모델을 바꿔야 해서 보류.

## 이미 후보로 정리된 단축키

`docs/keyboard-shortcuts.md` §6 "미구현 제안 단축키"에 `Ctrl+A` 전체 선택, `Ctrl+W` 탭 닫기, `Ctrl+L`/`F4` 경로 포커스, `Ctrl+D` 즐겨찾기 추가, `Ctrl+Shift+C` 경로 복사, `Ctrl+Z` 실행 취소, `Ctrl+H` 숨김 토글(토글 버튼은 이미 있음), `Space` 빠른 미리보기가 있다. 여기서는 중복해 적지 않는다.
