# 마크다운 뷰어 원격(https) 이미지 표시

- 상태: Todo

## 요구사항

마크다운 문서의 원격 이미지(`![](https://...)`)를 볼 수 있어야 한다. 표시 방식(항상 표시 / 문서별 허용 / 차단 유지)은 사용자 결정 대기.

## 원인 분석 또는 설계

### 현재 동작 (2026-10-16 앱에서 확인)

- 페이지 CSP는 `img-src ... http: https:`로 원격 이미지를 허용하지만, `MarkdownViewer.OnWebResourceRequested`가 모든 요청(`AddWebResourceRequestedFilter("*")`)을 받아
  내부 주소(`folderss-viewer`, `folderss-doc-asset`)가 아니면 403으로 막는다. 오류가 아니라 의도된 차단 응답이다.
- 확인용 문서(`https://img.shields.io/...` 배지, `https://github.githubassets.com/...` 이미지, `http://example.com/x.png`, 로컬 이미지)에서
  PC에서는 두 https 주소 모두 접속되는데(curl 200/301) 뷰어에서는 원격 이미지 3개가 모두 깨지고 로컬 이미지만 표시됐다.

### 시나리오별 영향

| 시나리오 | 현재 | 원격 이미지 허용 시 |
|---|---|---|
| ① GitHub README의 빌드 배지(`img.shields.io`), 스크린샷(`user-images.githubusercontent.com`) | 깨짐 | GitHub에서처럼 표시 |
| ② 로그인이 필요한 사내 위키·Confluence 첨부 이미지 | 깨짐 | 대부분 여전히 깨짐(뷰어는 브라우저 로그인 정보를 쓰지 않음) |
| ③ `http://` 이미지 | 깨짐 | 대부분 여전히 깨짐(보안 페이지의 혼합 콘텐츠 차단·자동 https 전환) |
| ④ 사외망 차단 환경 | 깨짐 | 깨짐(변화 없음) |
| ⑤ 받은 문서에 숨은 추적 이미지(`https://추적서버/pixel.png?user=...`) | 요청 안 나감 | 문서를 열기만 해도 요청이 나가 열람 시각·IP 노출 |

- ⑤는 웹 브라우저·GitHub 미리보기와 같은 수준의 노출이다. 스크립트 실행·파일 접근 위험은 없다(본문 HTML 정화·CSP 유지).

### 선택지

| 선택지 | 내용 | 비고 |
|---|---|---|
| A. https 이미지 항상 표시 | 처리기에서 `ResourceContext == Image`이고 `https`인 요청만 통과, 나머지 외부 요청은 계속 403 | 구현 간단, ⑤ 감수 |
| B. 문서별 "원격 이미지 보기" | 원격 이미지가 있으면 상단 안내 막대 → 누르면 그 문서에서만 허용(메일 프로그램 방식) | ⑤ 차단 가능, 구현 보통 |
| C. 차단 유지 | 현재와 같음 | |

- 추천: 직접 만들거나 GitHub에서 받은 문서를 주로 보면 A, 남이 보낸 문서를 자주 열면 B.
