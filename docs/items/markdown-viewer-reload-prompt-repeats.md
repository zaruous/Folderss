# 마크다운 뷰어 외부 변경 확인창 불필요 반복 표시 수정

- 상태: Verified (2026-07-14 사용자 확인 완료)

## 요구사항

마크다운 뷰어가 열려 있을 때 파일이 외부에서 변경되면 리로드 확인 메시지가 뜨는데,
이 메시지가 불필요하게 계속(반복적으로) 뜨는 문제를 수정한다.

## 원인 분석 또는 설계

`MarkdownViewer.ReloadExternalFileAsync()`에서 두 가지 원인이 겹쳐서 발생:

1. 사용자가 확인창에서 "아니오"를 선택해도 `_lastLoadedContent`는 갱신되지 않는다.
   이후 편집기와 무관한 워처 이벤트(메타데이터 갱신, 동기화 툴의 터치 등)가 다시 발생하면
   디스크 내용과 `_lastLoadedContent`가 여전히 다르므로 동일한 확인창이 계속 다시 뜬다.
2. `MessageBox.Show`는 중첩 메시지 펌프를 돌리기 때문에, 확인창이 떠 있는 동안에도
   `FileSystemWatcher` 콜백과 디바운스 타이머가 다시 실행될 수 있어 확인창이 중첩으로 뜰 수 있다.

## 구현 내용

- `_lastPromptedContent` 필드 추가 — 마지막으로 확인창을 띄운 외부 내용을 기억
- 디스크 내용이 `_lastPromptedContent`와 같으면(이미 물어봤고 거부한 내용과 동일) 재확인 없이 스킵
- `_reloadPromptOpen` 가드 추가 — 확인창이 열려 있는 동안 재진입 호출은 즉시 반환해 중첩 확인창 방지
- `Load()`에서 새 파일을 열 때 `_lastPromptedContent`를 초기화

### 추가 수정: "예" 선택 시 확인창을 띄우기 전 스냅샷이 로드되던 문제

실사용 검증 중, 확인창이 떠 있는 동안(모달 대기 중) 파일이 다시 변경되면 "예"를 눌러도
확인창을 띄우기 직전에 읽은 오래된 `content` 스냅샷이 그대로 로드되어, 최신 변경 내용이
아닌 이전 버전이 표시되는 문제 발견.

- "예" 응답을 받은 직후, `CallAppReloadContent`를 호출하기 전에 파일을 다시 읽어(`ReadAllTextAllowingWriters`)
  최신 내용(`latestContent`)을 사용하도록 변경. 재읽기 중 `IOException`/`UnauthorizedAccessException`이
  발생하면 기존 스냅샷(`content`)으로 폴백.

### 추가 수정 2: 확인창이 아예 안 뜨는 것처럼 보이던 문제 (owner 미지정)

`MessageBox.Show`를 owner 창 없이 호출하고 있었다. 외부 편집기에서 파일을 저장하는 시나리오에서는
그 시점에 앱이 백그라운드에 있으므로, owner 없는 확인창은 포커스를 얻지 못하고 다른 창 뒤에 숨어서 뜬다.
owner가 없으면 메인 윈도우도 modal로 잠기지 않아 앱은 평소처럼 동작하고, 사용자는 확인창이 안 뜬 것으로
인식한다. 게다가 숨은 확인창이 닫히기 전까지 `_reloadPromptOpen` 가드가 계속 걸려 있어 이후의 외부 변경에도
확인창이 전혀 뜨지 않는다.

- `Window.GetWindow(this)`로 owner를 구해 `MessageBox.Show(owner, ...)`로 호출하도록 변경.
  owner가 null이면(뷰어가 트리에서 분리된 경우) 기존 오버로드로 폴백.
