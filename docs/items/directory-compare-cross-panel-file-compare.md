# 폴더 비교 창 — 좌우 패널에서 고른 두 파일 비교 버튼

- 상태: Ready for Verification — 구현·단위 테스트 완료, Windows 화면 확인 대기

## 요구사항

- 2026-10-16 요청: 폴더 비교 창에서 비교할 파일을 바로 비교 화면으로 보고 싶다.
- 사용자 결정:
  - 더블클릭이 아니라, **왼쪽·오른쪽 패널에서 파일을 하나씩 고른 뒤 비교 버튼**으로 연다. 더블클릭·Enter는 지금처럼 기본 프로그램으로 연다.
  - 비교 화면은 **기존 두 파일 비교 창**(`FileCompareWindow`)을 쓴다.
  - 이름이 다른 두 파일도 비교할 수 있도록 **`같은 이름 따라 선택`을 켜고 끄는 체크**를 둔다(기본 켬).

## 원인 분석 또는 설계

- 오늘 이력(`directory-compare.md`): 더블클릭을 "짝이 있으면 비교, 없으면 열기"로 했다가 결과를 예측하기 어려워 "늘 열기"로 바꿨다. 이번에는 더블클릭은 그대로 두고 명시적인 버튼을 추가하므로 그 문제가 다시 생기지 않는다.
- 기존 "같은 이름 따라 선택"은 한쪽에서 고르면 반대쪽 선택을 같은 이름으로 바꾼다. 같은 이름이 없으면 선택을 지운다. 그래서 켠 상태에서는 이름이 다른 파일을 양쪽에 동시에 골라 둘 수 없다.
  - 켜 두면 한쪽에서 고를 때 반대쪽 같은 이름이 따라 골라진다. 버튼만 누르면 같은 이름 짝을 비교할 수 있다.
  - 끄면 양쪽을 따로 고른다.
- 버튼 활성 조건: 왼쪽 패널에서 파일 1개, 오른쪽 패널에서 파일 1개(폴더·여러 개·한쪽 없음이면 비활성). 왼쪽 파일이 왼쪽(변경 전)이다.
  - 버튼이 비활성일 때도 툴팁이 조건을 알려 준다(`ShowOnDisabled`). 활성일 때는 두 파일 이름을 보인다.
- 짝짓기는 비교 기준과 무관하다. 고른 그대로 쓰므로, 동기 이동이 끊긴 상태에서 서로 다른 폴더의 파일도 비교된다(사용자가 직접 골랐으므로 의도로 본다).
- `같은 이름 따라 선택` 체크는 저장하지 않는다. 창을 열 때마다 켜진 상태로 시작한다(가장 익숙한 기존 동작). `▲/▼ 차이` 이동의 따라 선택도 이 체크를 따른다.

## 구현 내용

- `CompareOverlay.CrossPanelFilePair` — 양쪽 선택(경로·폴더 여부)에서 [왼쪽, 오른쪽] 파일 쌍 또는 null. 순수 함수.
- `DirectoryCompareWindow`
  - 툴바에 `⇆ 파일 비교` 버튼과 `같은 이름 따라 선택` 체크를 추가했다(`▼ 다음 차이` 뒤).
  - 선택이 바뀔 때마다 버튼 상태·툴팁을 갱신한다. 따라 선택은 체크가 켜져 있을 때만 한다.
  - 누르면 파일이 아직 있는지 확인한 뒤 메인 창의 두 파일 비교 창을 연다. 없으면 상태 줄에 안내한다.

## 검증

- 새 테스트를 먼저 추가해 실패(함수 없음, 컴파일 오류)를 확인한 뒤 구현했다.
  - 파일 하나씩이면 [왼쪽, 오른쪽] 순서
  - 한쪽 없음·두 개·폴더·null이면 null
- Linux 전체: 335 통과·3 건너뜀·0 실패. 앱 본체 Linux 컴파일: 기존 콘솔 패널 오류 1종 외에 새 오류·경고 없음.
- **Windows에서 확인할 것**:
  - 양쪽에서 파일을 하나씩 고르면 버튼이 켜지고, 누르면 두 파일 비교 창이 열린다.
  - 체크를 끄고 이름이 다른 두 파일을 골라 비교할 수 있다.
  - 체크를 켠 상태에서는 기존처럼 같은 이름이 따라 골라진다.
  - 폴더를 고르거나 여러 개를 고르면 버튼이 꺼지고 툴팁에 조건이 보인다.
  - 툴바가 좁은 창 너비에서 잘리지 않는다(버튼 2개가 늘었다).
