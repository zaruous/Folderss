# 폴더 비교 창 — 좌우 폴더 패널 방식 재설계

- 상태: In Progress

## 요구사항

### 배경

- 2026-10-14에 전용 비교 창 1차 구현(커밋 `69298e2`)을 했다. 결과를 한 목록에 표로 늘어놓는 방식이다.
- 2026-10-15 사용자 확인 결과 마음에 들지 않음: "Beyond Compare의 폴더 비교 방식 조사가 덜 됐다", "폴더 패널을 좌우 두 개 배치해서 비교하는 방식이 좋다".
- Beyond Compare(이하 BC)를 조사해 좌우 정렬 트리(전용 컨트롤) 방식으로 재설계했으나(커밋 `99074a9`), 사용자 결정으로 아래 방향이 됐다.
  - 비교 창 안에 **기존 폴더 패널(`FolderBrowser`) 두 개를 좌우로 배치**하고, 가운데 분할선으로 너비를 조절한다.
  - 각 패널은 **자기 폴더의 실제 상태만** 보이고 그 위에 비교 상태를 겹친다. 반대쪽에만 있는 항목을 빈 줄로 끼워 넣어 줄을 맞추지 않는다.
  - 목록은 **현재 폴더 하나만** 보이고, 한쪽에서 하위 폴더로 들어가면 반대쪽도 같은 상대 경로로 따라 이동한다.
  - 비교 외에 **파일 이동 도구**로도 쓴다: `>`·`<`로 고른 항목을 반대쪽으로 이동, 복사는 Ctrl+C/V. 이 창에서 한 파일 작업은 **작업 이력** 사이드 패널에 남고 되돌릴 수 있다.

### 기능 요구사항

1. **좌우 폴더 패널 + 분할선**: 왼쪽·오른쪽에 `FolderBrowser`를 하나씩 두고, 경로 입력란·뒤로/앞으로/상위·이름 필터 같은 패널 기능을 그대로 쓴다. 가운데 세로 분할선으로 너비를 조절한다.
2. **비교 상태 겹치기**: 각 패널 목록 행에 상태(같음·다름·이쪽만·유형 다름·비교 불가)를 색과 `비교` 열로 보인다. 폴더 행은 하위 내용의 집계 상태. 반대쪽에만 있는 항목은 반대쪽 패널에서 "이쪽만"으로 보인다.
3. **같은 이름 따라 선택**: 한쪽에서 항목을 고르면 반대쪽에서 같은 이름(대소문자 무시) 항목을 선택하고 화면에 보이게 스크롤한다. 상태 줄에 같음·다름·왼쪽만·오른쪽만 개수.
4. **동기 이동**: 비교 기준 폴더 아래에서 한쪽이 하위·상위 폴더로 이동하면 반대쪽도 같은 상대 경로로 이동한다. 반대쪽에 그 폴더가 없으면 반대쪽은 제자리에 두고 "반대편에 이 폴더가 없음"을 알린다. 기준 밖으로 나가면 동기 이동을 멈추고, `비교`를 다시 누르면 두 패널의 현재 경로가 새 기준이 된다.
5. **차이만 보기**: 같음 항목을 숨긴다(패널마다 자기 목록에 적용).
6. **`>` / `<` 이동**: 고른 항목(다중 선택 가능)을 반대쪽 패널의 현재 폴더로 **이동**한다.
   - 반대쪽에 같은 이름이 있으면 **교체**: 확인 창에 교체될 항목을 보이고, 대상의 옛 항목은 휴지통으로 보낸 뒤 옮긴다. 대상이 더 최신(수정 시각)인 파일은 확인 창에 따로 표시한다. 양쪽에 있는 폴더를 교체하면 "대상 폴더에만 있는 항목 n개도 휴지통으로 간다"를 함께 경고한다.
   - 이동할 폴더의 하위 파일이 기준 개수(옵션, 처음 100개) 이상이면 확인 창을 띄운다. 확인 창의 "확인하였습니다(다시 묻지 않음)" 체크는 **이 창을 닫을 때까지** 이 개수 확인만 생략한다.
7. **복사 = Ctrl+C / Ctrl+V**: 일반 파일 복사·붙여넣기와 같은 동작. 비교 창 안에서도 동작해야 한다(현재는 동작 안 함 — 아래 "기존 결합"). 잘라내기(Ctrl+X)는 막는다 — 다른 곳(탐색기 등)에 붙여넣으면 이력 밖에서 이동이 일어나기 때문. 이동은 `>`/`<`로만.
8. **삭제 = Delete**: 비교 창 안에서 Delete를 처리한다(휴지통). Shift+Delete 영구 삭제는 되돌릴 수 없으므로 작업 이력에서 "되돌리기 불가"로 표시한다.
9. **작업 이력 사이드 패널**: 이 창에서 한 이동·복사·삭제를 시간순으로 보이고, 최근 작업부터 차례로 되돌린다. 파일 내용 편집은 기록하지 않는다. 이력은 작업 로그(항목별 성공·실패, 오류 메시지, 되돌리기 결과)와 함께 디스크에 저장하고 **7일이 지나면 지운다**.
10. **이력에 남지 않는 파일 작업은 비교 창에서 막는다**(안전 모드): Windows 셸 우클릭 메뉴, 끌어다 놓기(들여오기·내보내기), 잘라내기. 대신 앱 자체 우클릭 메뉴로 이력에 남는 동작만 제공한다(아래 "비교 패널 안전 모드").
11. 양쪽에 있는 파일을 더블클릭하면 두 파일 비교 창을 연다(1차와 같음).
12. 비교는 백그라운드에서 돌고 중지할 수 있다. 파일 작업 뒤에는 자동으로 다시 비교한다.
13. **옵션**: 1차의 `비교 ▾`(권장값 기본)에 표시 옵션과 이동 확인 기준을 더한다(아래 "옵션").

### 범위 밖 (이번 재설계에서 하지 않음)

- BC식 트리 펼침, 좌우 줄 맞춤(빈 줄 끼우기), 동기화 프리셋(갱신·미러), 세분 필터(왼쪽 최신 등).
- 다른 프로그램(탐색기 등)이 비교 중인 폴더를 바꾼 것의 이력 기록 — 앱이 알 수 없다. 목록 변경을 감지하면 "변경됨 — 다시 비교"를 보이고, 그 파일의 되돌리기는 크기·시각 검사에서 막힌다.
- 이름 바꾸기·새 폴더·새 파일 — 메인 창 단축키라 비교 창에서는 원래 동작하지 않는다. 필요하면 이력에 남는 동작으로 별도 추가.
- 메인 창에서 한 파일 작업의 이력 기록, 파일 내용 편집 기록.
- 메인 창의 좌우 폴더 패널에 직접 겹치는 방식 — `folder-panel-compare-mode.md`(이 창 완성 후 필요 여부 재판단).

## 원인 분석 또는 설계

### 화면 배치

```
┌ 폴더 비교 ────────────────────────────────────────────────────────────────────────────────┐
│ [⟳ 비교][▾] [■ 중지]  [☑ 차이만 보기]  [▲ 이전 차이][▼ 다음 차이]  [⇄ 좌우 바꾸기]  [☰ 작업 이력]    │
│ ┌ 왼쪽 폴더 패널 ───────────────┐ ┃ ┌ 오른쪽 폴더 패널 ──────────────┐ ┌ 작업 이력 ──────────┐ │
│ │ ← → ↑ [D:\work\proj\src     ] │ ┃ │ ← → ↑ [D:\backup\proj\src   ] │ │ 10:42 이동 → 3개    │ │
│ │ 이름        수정한 날짜  비교  │[>]│ 이름        수정한 날짜  비교  │ │   App.cs (교체)     │ │
│ │ 📂 Services 10-14 22:40  ≠    │[<]│ 📂 Services 10-01 09:10  ≠    │ │ 10:40 복사 ← 1개    │ │
│ │ 📄 App.cs   10-14 22:40  ≠    │ ┃ │ 📄 Old.cs   09-01 10:00  ▶    │ │ 10:38 삭제 1개      │ │
│ │ 📄 New.cs   10-14 21:00  ◀    │ ┃ │ 📄 App.cs   10-01 09:10  ≠    │ │                     │ │
│ └───────────────────────────────┘ ┃ └───────────────────────────────┘ │ [되돌리기]           │ │
│ 기준: D:\work\proj\src ↔ D:\backup\proj\src · 현재: \ · 같음 28 · 다름 5 · 왼쪽만 4 · 오른쪽만 3     │
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

- 본문은 `Grid` 열: 왼쪽 패널 `*` | 분할선 + `>`/`<` 버튼 | 오른쪽 패널 `*` | 작업 이력(열고 닫기, 너비 조절).
- 분할선은 `GridSplitter`(`ResizeBehavior=PreviousAndNext`), 각 패널 최소 200px. 두 번 누르면 반반. 비율은 저장하지 않는다.
- `>`·`<`는 분할선 위에 세로로 둔다(어느 쪽으로 가는지 위치로 보이게). 선택이 없으면 비활성.

### 기존 결합 (코드 확인 결과)

- `FolderBrowser`는 `Window.GetWindow(this) as MainWindow`로 메인 창을 찾는다(붙여넣기 `Paste_Executed`, 잘라내기 표시, 끌어다 놓기, 패널 잠금 검사 등 7곳). 비교 창 안에서는 null이라 **붙여넣기·놓기가 조용히 아무것도 안 한다**.
  → 도우미 하나로 해결: "내 창이 `MainWindow`가 아니면 그 창의 `Owner`가 `MainWindow`인지" 본다. 비교 창은 `Owner = MainWindow`로 열리므로 붙여넣기·잘라내기 상태·잠금 검사가 메인 창 것을 그대로 쓴다(비교 창에서 잘라내고 메인 창에 붙여넣기도 됨). 끌어다 놓기도 덤으로 동작한다.
- F5/F6/Delete는 `MainWindow.Window_KeyDown`이 `ActivePane`/`TargetPane`으로 처리한다. 비교 창에는 해당하지 않으므로 `>`/`<`/Delete를 비교 창이 직접 처리한다. 패널 잠금 검사는 메인 창의 `IsPathPinLocked`/`IsDestinationPinLocked`를 부른다.
- **기존 이동은 같은 이름을 덮어쓰지 않는다**: `FileOperationService.Move`는 대상에 같은 이름이 있으면 `App (2).cs`처럼 번호를 붙인다(`GetUniquePath`). `>`/`<`의 교체는 "대상 옛 항목을 휴지통으로 → 이동"을 비교 창 쪽에서 순서대로 한다. Ctrl+V 붙여넣기는 기존 동작(번호 붙이기)을 그대로 둔다.
- `NavigateTo`는 없는 폴더면 메시지 상자를 띄운다. 동기 이동은 반대쪽에 폴더가 있는지 먼저 확인하고 부른다.

### 비교 패널 안전 모드

비교 창의 두 `FolderBrowser`는 "이력에 남는 작업만 허용" 모드로 연다(`FolderBrowser`에 속성 하나 추가, 메인 창 패널은 기존 그대로).

| 경로 | 지금 | 안전 모드 |
|---|---|---|
| 목록·폴더 트리 우클릭 | Windows 셸 메뉴(`ShellContextMenuService`) — 삭제·이름 바꾸기·잘라내기·붙여넣기·다른 프로그램 확장 메뉴까지 앱 밖에서 처리 | 앱 자체 메뉴: 반대쪽으로 이동(`>`/`<`), 복사, 붙여넣기, 삭제(휴지통), 선택한 두 파일 비교, 경로 복사, 탐색기에서 위치 열기 |
| 끌어다 놓기 들여오기 (`FileList_Drop`) | `FileOperationService.Copy/Move/CreateShortcut` 직접 실행 | 막음(놓기 불가 커서) |
| 끌어다 내보내기 (`DoDragDrop`, 이동 허용) | 탐색기로 끌면 이동될 수 있음 | 막음 |
| 잘라내기 Ctrl+X | 붙여넣는 곳에서 이동 | 막음 |
| 복사 Ctrl+C | 클립보드에 넣기만 함 | 그대로(원본은 안 바뀜) |
| 붙여넣기 Ctrl+V | 메인 창이 처리 | 메인 창 처리 + 결과를 이력에 기록 |
| 더블클릭·Enter 열기 | 기본 프로그램으로 열기 | 그대로(파일 내용 편집은 이력 범위 밖), 양쪽에 있는 파일은 두 파일 비교 |

- "탐색기에서 위치 열기"는 앱 밖으로 나가는 통로지만, 거기서 한 작업은 앱이 막을 수 없다. 비교 창에서 바뀐 것을 감지하면 "변경됨"으로만 알린다.

### 동기 이동 규칙

- 처음 비교할 때 두 패널 경로가 비교 기준(루트) 쌍이 된다.
- 한쪽 `PathChanged` → 루트 기준 상대 경로 → 반대쪽 같은 상대 경로가 있으면 `NavigateTo`. 재진입 방지 플래그로 핑퐁을 막는다.
- 반대쪽에 없으면 반대쪽은 제자리, 상태 줄에 알림.
- 어느 쪽이든 루트 밖으로 나가면 동기 이동과 오버레이를 멈추고 "기준 밖 — 비교를 누르면 현재 경로로 다시 비교"를 보인다.

### 작업 이력과 되돌리기

기록 단위는 "작업 한 번"(예: `>`로 3개 이동)이고 그 안에 항목별 기록을 둔다.

| 작업 | 항목별 기록 | 되돌리기 |
|---|---|---|
| 이동 `>` `<` | 원래 경로 → 옮긴 경로, 교체했다면 휴지통으로 보낸 대상 옛 항목의 원래 경로 | 옮긴 것을 원래 경로로 되돌리고, 교체로 휴지통에 간 항목을 원래 자리로 복원 |
| 복사 Ctrl+V (Ctrl+X+V는 이동) | 원본 → 만들어진 경로 | 만들어진 항목을 휴지통으로 |
| 삭제 Delete | 휴지통으로 보낸 원래 경로 | 휴지통에서 원래 자리로 복원 |
| 영구 삭제 Shift+Delete | 원래 경로 | **불가**(이력에 표시만) |

- **되돌리기 조건 검사**: 각 항목의 크기·수정 시각을 기록해 두고, 되돌릴 때 지금 상태가 기록과 다르면(그 사이 바뀜·지워짐) 그 작업 되돌리기를 막고 이유를 보인다. 원래 자리에 같은 이름이 새로 생겼으면 덮어쓰지 않고 막는다.
- **휴지통 복원**: Windows 셸(`Shell.Application`의 휴지통 네임스페이스)에서 원래 경로·삭제 시각으로 항목을 찾아 복원한다. 휴지통을 비웠거나, 휴지통 크기 제한으로 바로 지워졌거나, 네트워크 드라이브(휴지통 없음)면 복원할 수 없다 → 되돌리기 불가로 표시. 확인 창에서 "휴지통으로" 갈 수 없는 위치면 미리 경고한다.
- **되돌리기 순서는 최근 작업부터(LIFO, Ctrl+Z와 같음)**. 이력 패널에서는 맨 위(가장 최근) 작업만 되돌리기가 켜진다. 오래된 작업부터 되돌리면(FIFO) 뒤 작업이 그 결과를 이미 옮겼거나 지웠을 수 있어 경로가 꼬인다. 예: ① `App.cs`를 오른쪽으로 이동 → ② 오른쪽 `App.cs`를 삭제. ①부터 되돌리면 오른쪽에 `App.cs`가 없어 실패하고, ②부터 되돌려야 ①도 된다.
- **저장**: `%LOCALAPPDATA%\Folderss\compare-history\<yyyy-MM-dd>.jsonl` — 한 줄이 기록 하나(작업 시작·항목별 결과·작업 끝·되돌리기). 비교 창을 열 때 7일 지난 파일을 지운다. 재시작 후에도 이력이 보이고 되돌리기는 위 조건 검사를 거친다.
- **기록 먼저, 실행 나중**: 작업마다 "시작(계획)"을 먼저 쓰고 실행 후 "끝"을 쓴다. 기록 쓰기가 실패하면 작업을 실행하지 않고 이유를 보인다(이력에 안 남는 작업을 막는다는 원칙). 예외는 빈 `catch`로 삼키지 않는다(프로젝트 규칙). "시작"만 있고 "끝"이 없는 작업(도중 종료)은 이력에 "중단됨 — 확인 필요"로 보이고 항목별 결과까지만 되돌린다.
- 7일 삭제는 기록만 지운다. 휴지통에 간 항목은 Windows 휴지통 규칙을 따른다.

### 옵션 (`비교 ▾` 대화상자)

1차 옵션(판정 기준·허용 오차·ignore·깊이·숨김) 아래에 묶음을 추가하고 `compare-settings.xml`에 저장한다. 표시 옵션은 바꿔도 다시 스캔하지 않고 오버레이만 다시 입힌다.

| 옵션 | 선택지 | 처음 값 | 이유 |
|---|---|---|---|
| 상태 색 | 상태별 색 / 방향 색(최신 빨강·오래됨 회색·한쪽만 보라, BC식) | 상태별 색 | 방향 색은 수정 시각 기준이라 복사·git checkout으로 시각만 바뀐 파일을 "최신"으로 잘못 보인다. 방향 색을 고르면 이 경고를 보인다 |
| 폴더 트리 | 보임 / 숨김 | 숨김 | 좌우 패널 + 이력 패널이라 너비가 좁다 |
| 미리보기 | 보임 / 숨김 | 숨김 | 같은 이유 |
| 차이만 보기 | 켬 / 끔 | 끔 | 처음엔 전체를 보여 줘야 같음도 확인된다. 툴바 체크로도 바꾸고 마지막 값을 기억 |
| 폴더 이동 확인 기준 | 하위 파일 n개 이상이면 확인 | 100 | 0이면 항상 확인 |

### 비교 실행

- 1차 서비스가 기준 아래 전체를 한 번에 판정하고, 오버레이는 결과에서 현재 폴더의 직속 항목만 골라 입힌다. 하위 폴더로 이동해도 다시 스캔하지 않는다.
- `>`/`<`/Ctrl+V/Delete/되돌리기 뒤에는 자동으로 다시 비교한다. 셸 우클릭 메뉴 작업 등으로 목록이 바뀌면 "변경됨 — 다시 비교"를 표시.
- 큰 트리에서는 결과가 늦게 나온다(점진 반영은 1차 서비스에 없음). 진행 표시(읽은 폴더 수)로 두고, 느리면 별도로 판단.

## 구현 단계

단계마다 빌드·테스트 후 커밋한다. 3단계부터 Windows 화면 확인이 필요하다.

1. **순수 로직 + 테스트** — 완료 조건: 아래 테스트 통과.
   - `CompareOverlay`: 현재 폴더 직속 항목만, 이름 대소문자 무시 짝짓기, 폴더 집계 상태, 이쪽만/유형 다름, 기준 밖 경로는 오버레이 없음.
   - `FileOperationJournal`: 이동·교체·복사·삭제 기록과 되돌리기(임시 폴더 실제 파일), 최근 작업만 되돌리기 가능, 그 사이 바뀐 파일·원래 자리에 새로 생긴 이름이면 되돌리기 거부, 영구 삭제는 불가 표시, 기록 쓰기 실패 시 작업 미실행, "끝" 없는 작업은 중단됨, 7일 지난 기록 파일 삭제, 저장 후 다시 읽어 같은 이력. 휴지통 복원은 Windows 전용이라 단위 테스트에서는 휴지통 대신 쓰는 경로를 주입해 검사한다.
2. **메인 창 찾기 도우미 + 붙여넣기 결과 반환** — 완료 조건: 빌드·기존 테스트 통과, 메인 창의 붙여넣기·놓기·잠금 동작 변화 없음(Windows 확인).
3. **FolderBrowser 오버레이·안전 모드** — `FileSystemItem` 필드, 오버레이 적용·해제, `비교` 열, 차이만 보기, 테마 색 키(`Themes/*.xaml` 8개), 안전 모드(셸 메뉴 → 앱 메뉴, 끌어다 놓기·잘라내기 막기). 완료 조건에 메인 창 패널은 안전 모드가 꺼져 기존과 같음을 포함.
4. **비교 창 재작성** — 좌우 패널·분할선·`>`/`<`(교체·개수 확인 창)·Delete·툴바·옵션·동기 이동·같은 이름 따라 선택·작업 이력 패널·되돌리기·휴지통 복원.
5. **정리·문서** — `DirectoryCompareView` 삭제, README·architecture, CLAUDE.md 테마 체크리스트에 색 키 추가.
