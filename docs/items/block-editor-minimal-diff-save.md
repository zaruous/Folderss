## 요구사항

#81 마지막 단계. 판단 자료(`block-editor-viewer-switch.md` "3. 기본 뷰어 전환 검토")의 가장 큰 막힘 요인 — **블록 편집기가 저장할 때 문서 전체를 정규형으로 다시 써서
남이 쓴 `.md`를 한 글자만 고쳐도 diff가 커지는 문제** — 를 없애고, 권장대로 매핑이 아닌 **설정 기본값부터** 블록 편집으로 바꾼다.

1. 최소 변경 저장: 바뀐 블록만 다시 쓰고 바뀌지 않은 블록은 원문 줄을 바이트 그대로. 블록 사이 구분자(빈 줄)도 원문 보존. 줄 끝(CRLF/LF)·BOM·끝 줄바꿈 유무는 파일 단위로 보존.
   사이드카 해시(#78)·`marks`(#76) 동작 유지, 실행 취소·외부 변경 다시 읽기·뷰어 전환 위치(줄 번호)와 일관.
2. 설정 > 뷰어 ".md 탭을 처음 열 때"의 기본값을 `블록 편집`으로. `.md` 매핑(`ViewerConfigService`)은 그대로, 이미 저장한 `defaultView`는 존중, 파일별 마지막 보기 우선 유지.
   블록 편집기가 열 수 없는 파일(32MB 초과)은 미리보기로.
3. 남은 격차 재점검·기록.

원칙: 1만 줄 문서 성능 유지(열기, 저장 시간 측정 기준 기록, 글자 입력 ≤ 20ms), 원문 구간 보관이 메모리를 과하게 늘리지 않게.

## 설계

### 원문 구간 단위 — 조각

- `BlockMarkdown.ParseCore(markdown, sources)`가 블록마다 `BlockSourceInfo`를 기록한다(기존 `Parse`는 `sources = null`로 같은 경로 — 기록 비용 없음).
  - 조각 = 블록 하나가 차지한 원문 줄 `[Start, End)`: 문단·목록 항목은 이어지는 줄까지(Setext 제목은 밑줄 줄까지), 코드·수식은 펜스까지, 인용·콜아웃·원문(HTML 등)은 그 줄들,
    표는 머리글 행 + 구분 행이 한 조각이고 나머지 행은 한 줄씩, front matter는 `---`~`---`, 토글은 **여는 줄+summary 조각**과 **`</details>` 조각** 두 개(자식은 각자 조각).
  - 조각 사이 줄(빈 줄, 공백만 있는 줄)은 구분자. 원문 = 앞 구분자 + 조각 + 구분자 + … + 조각 + 끝 구분자.
  - 쓰던 형식: 첫 줄 들여쓰기 열, 목록 표식(`*`·`+`·`-`, `.`·`)`), 표식 뒤 공백 수, 목록 첫 번호 항목의 번호(시작 번호), 내용 시작 열, Setext 밑줄.
  - 토글 안 자식은 토글 들여쓰기를 뺀 줄로 다시 읽으므로 줄 번호 대응표(`lineMap`)로 문서 줄을 찾는다. 줄을 나눌 수 없는 토글(한 줄 토글 `<details><summary>…</summary>…</details>`,
    닫히지 않은 토글, `글</details>`처럼 닫는 줄에 글이 붙은 토글)은 그 토글(과 닫는 줄의 글)을 기록하지 않는다 → 그 부분만 늘 정규형.
- `MarkdownSource.Parse`(`Services/BlockMarkdown.Source.cs`)가 위 정보를 블록 `Id`로 바꿔 보관하고, 곧바로 블록을 정규형으로 써 보며(`BlockMarkdown.WritePieces`) 조각마다
  정규형 글의 해시(FNV-1a 64비트)를 기억한다. 원문 글자열은 뷰어가 이미 들고 있는 `_diskText`와 같은 객체를 참조하고, 따로 두는 것은 줄 시작 위치 배열과 블록당 객체 하나(`BlockSourceInfo`)뿐.

### 변경 판정

- 저장할 때 `WritePieces`가 지금 블록을 같은 방식으로 쓰며 조각마다 `PieceWriter.Piece`를 부른다. **같은 `Id`·같은 조각의 정규형 글(문맥 포함)이 읽을 때와 같으면 원문 줄 그대로**, 다르면 정규형.
  - 문맥 포함: 번호, 들여쓰기 열, 표 열 수, 토글 접힘(여는 줄), 할 일 체크, 코드 언어, 콜아웃 종류, 이미지·카드 경로가 모두 그 조각 글에 들어가므로 하나라도 바뀌면 다시 쓴다.
  - 번호 목록의 두 번째 항목부터는 번호 숫자를 빼고 비교한다 — `1. 1. 1.` 형식 목록 가운데 항목을 넣거나 지워도 뒤 항목 줄은 그대로.
  - 사이드카 속성(블록 색·`marks` 등)은 Markdown에 나타나지 않으므로 판정에 들지 않는다(속성만 바꾸면 Markdown은 바이트 동일, 사이드카만 다시 씀).
  - `EditorBlock.Clone`은 `Id`를 유지하므로 실행 취소로 되돌린 블록은 다시 원문 조각이 된다. 새 블록·`Duplicate`·붙여넣은 블록은 새 `Id` → 정규형.
- 구분자: 앞뒤 조각이 원문에서도 바로 이웃이었으면 원문 구분자(빈 줄 개수 그대로), 아니면(사이에 블록을 넣거나 지움, 옮김) 정규형 구분자(목록 항목 사이 0줄, 그 밖 1줄).
  첫 조각이 원문 첫 조각이면 앞 빈 줄, 마지막 조각이 원문 마지막 조각이면 끝 빈 줄도 원문.
- 다시 쓰는 블록의 형식: 원래 있던 블록은 원래 목록 표식·표식 뒤 공백·시작 번호·들여쓰기 열(부모 안·코드 블록이 되지 않는 범위, 같은 수준 앞 항목 안으로 들어가지 않는 범위)·Setext 제목을 따르고,
  새 목록 항목은 같은 목록 바로 앞 항목의 표식·들여쓰기를 따른다(`*` 목록에 `-` 항목이 끼면 CommonMark에서 목록이 둘로 갈라짐). 원문 그대로 쓴 목록 항목의 자식은 원문 내용 열 기준으로 들여쓴다.
- 바뀐 것이 없으면(조각 순서·`Id`·해시가 읽을 때와 모두 같음 — 개수와 누적 해시로 비교) 원문 글자열 자체를 돌려준다(`Mode` 0). 토글 예외 등 조각을 기록하지 못한 블록이 있어도 무편집 저장은 바이트 동일.

### 안전장치

결과를 다시 `Parse`해 블록 구조(`MarkdownSource.SameStructure`: 종류·상대 들여쓰기·본문·체크·접힘·언어·콜아웃 종류·경로·표 머리글 정렬)가 저장할 블록과, 아니면 정규형을 다시 읽은 것과 같은지 확인한다.

1. `Mode` 1: 바뀐 조각만 정규형 — 보통의 경우.
2. `Mode` 2: 1이 구조를 바꾸면(예: 목록 가운데 항목을 문단으로 바꾸면 원문 구분자 "빈 줄 없음" 때문에 앞 항목의 이어지는 줄이 됨) 바뀐 조각이 든 **최상위 묶음**(이어진 최상위 목록 항목들·표 전체, 최상위 블록 + 자식)을
   통째로 정규형(목록 표식·시작 번호만 원문)으로 쓰고 묶음 안팎 구분자도 정규형.
3. `Mode` 3: 그래도 다르면 문서 전체 정규형(예전 동작).

무작위 편집 300회(종류 바꾸기·지우기·넣기·내어쓰기 1~3개) 측정: `Mode` 0 27회 · 1 264회 · 2 9회 · 3 0회, 300회 모두 구조 보존.

### 줄 끝·인코딩

- 줄 끝: 원문에 `\r\n`이 하나라도 있으면 CRLF(예전 `_crlf` 판단과 같음) — 다시 쓴 조각과 정규형 구분자도 CRLF. 원문 그대로 쓴 조각은 원래 줄 끝 그대로(섞인 파일도 그 조각은 보존).
- 끝 줄바꿈: 원문이 줄바꿈 없이 끝났으면 저장 결과도 마지막 줄바꿈을 뗀다. 원문 마지막 줄(줄바꿈 없음) 뒤에 블록을 붙이면 그 사이에 줄바꿈을 넣는다.
- BOM·인코딩은 예전처럼 뷰어가 읽은 인코딩(`MarkdownViewer.DetectEncoding`)으로 쓴다. `BlockEditor.GetMarkdown`이 이제 파일에 쓸 글(줄 끝 포함) 그대로를 돌려주므로
  `BlockEditorViewer.Save`의 `\n → \r\n` 바꾸기를 없앴다(원문 CRLF 줄이 `\r\r\n`이 되지 않게). 상태 줄 CRLF/LF 표시는 그대로.
- front matter는 이미 바이트 보존이었고(원문을 `Text`로 보관), 이제 같은 조각 구조로 통합됐다 — 속성을 고치면 그 블록 조각만 다시 쓰는데 `Text`가 원문 줄이므로 실제 diff는 고친 속성 줄뿐.

### 다른 기능과의 일관성

- **사이드카(#78)·`marks`(#76)**: `BlockSidecar.Serialize(blocks, 저장 글)`은 저장 글을 다시 읽은 블록으로 해시를 낸다. 안전장치가 저장 글의 구조 = 저장할 블록(또는 정규형 재읽기)임을 보장하므로 해시·순번이 예전과 같다.
  최소 변경 저장 후 다시 읽어 속성이 같은 블록에 붙는지 단위 테스트로 확인(`Sidecar_AttributesStillReattachAfterMinimalSave`).
- **실행 취소**: 기준은 읽은 시점 원문이고 저장해도 바꾸지 않는다. 저장 뒤 실행 취소로 읽은 상태로 돌아가 다시 저장하면 원문과 바이트 동일.
- **외부 변경 다시 읽기**: `ApplyContent` → `SetMarkdown`이 새 원문으로 기준을 다시 잡는다.
- **뷰어 전환 위치(줄 번호)**: `MarkdownSaveResult.BlockLines`(저장될 글 기준 블록별 시작 줄)로 계산한다 — 디스크 원문과 줄이 맞는다(예전에는 정규형 기준이라 손으로 쓴 원문과 몇 줄 어긋남).
  `MarkdownViewSwitch.FromBlock`/`ToBlock`에 선택 인자 `blockLines`, 표 기반 `BlockAtLine(IReadOnlyList<int>, line)`을 더했다(기존 정규형 경로는 `Mode` 3과 테스트용으로 남김).
  부수 효과로 `ToBlock` 줄 번호 경로가 "이분 탐색마다 `Serialize` 두 번"에서 "저장 계산 한 번 + 이분 탐색"으로 바뀐다(1만 줄에서 수십 ms → 저장 계산 시간).

### 기본 보기 기본값

- `MarkdownViewSwitch.DefaultViewWhenUnset = "blocks"`. `MarkdownViewSettings`는 파일이 없거나 `defaultView` 항목이 없거나 JSON이 깨졌으면 이 값, `defaultView`가 저장돼 있으면 그 값(`mapping`·`blocks`·`preview`,
  알 수 없는 값은 예전처럼 `mapping`). 고르는 순서는 그대로: 파일별 마지막 보기 → 기본 보기 → 매핑. `.md` 매핑(`ViewerConfigService`)은 바꾸지 않았다.
- 주의: 예전 빌드도 `markdown-view.json`을 쓸 때마다 `defaultView`(당시 기본 `mapping`)를 함께 저장했다. 그래서 **전환 버튼을 한 번이라도 눌렀거나 설정 창에서 저장한 기존 사용자는 `mapping`이 저장돼 있어 계속 Markdown 뷰어로 열린다**(요구대로 저장값 존중).
  설정 > 뷰어에서 `블록 편집 (기본값)`을 고르면 바뀐다.
- 설정 창 콤보: `블록 편집 (기본값)` 표시, 저장 실패 대체값도 새 기본값. 설명 문구에 큰 파일·최소 변경 저장 안내.
- 큰 파일: `ViewerHost.OpenFile`이 `ChooseViewerKey(…, blocksUnavailable: 파일 크기 > BlockEditorViewer.MaxFileBytes)`로 고른다 — 블록 편집으로 고른 경우(기억·기본값·매핑 모두) 미리보기(Markdown 뷰어)로 연다.
  Markdown 뷰어 자체는 5MB 넘으면 미리보기를 끈 원문 편집 모드로 연다(기존). 전환 버튼으로 직접 `블록 편집`을 누르면 예전처럼 블록 편집기가 "파일이 커서 열지 않았습니다" 안내를 보인다.

## 보존되지 않는 경우 (알려진 한계)

| 경우 | 결과 |
|---|---|
| 고친 블록 **안**의 형식 | 그 블록만 정규형: 표 행 `| a | b |`(정렬 공백·앞뒤 `|` 생략 형식 사라짐), `~~~` → ` ``` `, ATX 닫는 `##` 제거, 줄 끝 공백 두 칸(하드 줄바꿈) 사라짐(파서가 줄 끝 공백을 버림 — 예전부터), 지연 이어쓰기 줄은 들여써짐, 탭 들여쓰기는 공백으로 |
| 블록을 넣거나 지우거나 옮긴 자리의 빈 줄 | 정규형(목록 항목 사이 0줄, 그 밖 1줄). 느슨한 목록(항목 사이 빈 줄)에 항목을 넣으면 그 자리만 빈 줄 없이 |
| 번호 목록 첫 항목을 지움 | 다음 항목이 첫 항목이 되며 정규형 번호(1부터)로 다시 씀. 구분 기호가 다른 이웃 목록(`3)` 다음 `1.`)은 파서가 한 목록으로 보므로 새 항목 번호가 이어짐(렌더링은 같음) |
| 표 열 추가·삭제, 열 수가 바뀌는 행 편집 | 표 전체 다시 씀(열 수가 모든 행에 들어감). 정렬 변경은 머리글+구분 행만 |
| 줄을 나눌 수 없는 토글(한 줄·닫히지 않음·`글</details>`) | 문서 어디든 고치면 그 토글 여는/닫는 줄은 정규형(무편집 저장은 바이트 동일) |
| 4칸 이상 들여쓴 원문(들여쓰기 코드) | 고치면 정규형 |
| 안전장치 `Mode` 2·3 | 묶음 전체 또는 문서 전체 정규형(드묾) |
| 섞인 줄 끝(LF·CRLF) 파일 | 원문 조각은 보존, 다시 쓴 조각은 CRLF |
| 줄 안 서식(#76) | 서식 입력란으로 고친 블록은 서식 직렬화 결과(예: `__굵게__` → `**굵게**`)가 될 수 있음 — 고친 블록 안 |
