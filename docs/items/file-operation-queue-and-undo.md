# 파일 작업 대기열·진행률 창 + 메인 패널 실행 취소(Ctrl+Z)

- 상태: Ready for Verification

## 요구사항

사용자가 고른 기능 두 개를 한 작업으로 묶는다.

1. **큰 파일·네트워크 복사의 진행률·취소** — 지금 메인 패널의 복사·이동·삭제는 UI 스레드에서 동기로 실행돼 큰 복사 중에는 앱이 멈춘 것처럼 보이고, 진행률·취소가 없다.
   - 복사·이동(반대편 패널 `F6`, 붙여넣기 `Ctrl+V`, 끌어다 놓기)과 삭제(`Delete`/`Shift+Delete`)를 백그라운드에서 실행한다.
   - 진행률 창에 파일 수·바이트·속도·남은 시간을 보이고 일시정지·취소할 수 있다. 여러 작업은 대기열로 차례로 실행한다.
   - 이름 충돌: 바꾸기 / 건너뛰기 / 둘 다 유지 + "나머지 충돌에도 적용". 기본값은 가장 안전한 선택.
   - 끝나면 관련 패널을 새로 고치고, 실패는 모아서 요약한다.
2. **메인 패널 파일 작업 실행 취소(`Ctrl+Z`)** — 메인 패널에서 한 마지막 작업(복사·이동·휴지통 삭제·이름 변경·새 폴더·새 파일)을 `Ctrl+Z`와 메뉴로 되돌린다.
   - 영구 삭제는 되돌릴 수 없음을 분명히 한다.
   - 작업 뒤 결과가 바뀌었으면 확인을 받은 뒤 진행한다(바뀐 항목은 건드리지 않음).
   - 중간에 취소한 작업은 기록된 만큼만 되돌린다.
   - 휴지통이 없는 네트워크·이동식 드라이브, 긴 경로, 잠긴 파일을 처리한다.
   - 폴더 비교 창의 작업 이력(`FileOperationJournal`)을 재사용하되 비교 창 동작과 기존 테스트는 깨지지 않아야 한다.
3. 단축키 추가 체크리스트(AGENTS.md "단축키 추가 시")와 설정 파일 저장 규칙을 지킨다.

## 원인 분석 또는 설계

### 현재 코드

- `MainWindow.ExecuteTransfer`(F6), `TryPasteFromClipboardInto`(Ctrl+V), `DeleteSelected`(Delete), `FolderBrowser.FileList_Drop`(끌어다 놓기)이 항목마다 `FileOperationService.Copy/Move/MoveToRecycleBin/DeletePermanently`를 UI 스레드에서 부른다.
  `Copy`는 파일 `File.Copy`, 폴더는 자체 재귀 복사라 진행률·취소가 없다.
- 같은 이름이 있으면 복사·이동 모두 묻지 않고 `이름 (2)`를 붙인다(`GetUniquePath`).
- 메인 패널 `Delete`는 VB `FileSystem`(`UIOption.OnlyErrorDialogs` = 확인 없음)로 휴지통에 보내는데, 네트워크·이동식 드라이브에는 휴지통이 없어 **확인 없이 영구 삭제**된다(기존 위험).
- 끌어다 놓기에서 이동하면 놓는 쪽이 이동을 끝낸 뒤 `DragDropEffects.Move`를 돌려준다. 이는 셸 규약상 "최적화되지 않은 이동"(원본 쪽이 지움) 신호다. 동기 처리라 원본이 이미 없어 문제가 드러나지 않았지만, 백그라운드로 바꾸면 탐색기가 아직 복사 중인 원본을 지울 수 있다.

### 조사에서 가져온 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 실행 방식 | **대기열(한 번에 하나, 먼저 넣은 것부터)**. 진행 중 작업은 일시정지·취소, 대기 중 작업은 빼기 | TC F2 대기열·TeraCopy와 같음. 탐색기처럼 나란히 돌리면 같은 디스크에서 서로 느려지고, "A 복사 → A 삭제"처럼 이어지는 작업이 순서를 잃어 위험. 실행 취소 이력의 순서도 실행 순서와 같아진다 |
| 진행률 표시 | 한 창(`파일 작업`)에 모든 작업. 작업마다 막대·파일 수·바이트·속도(최근 몇 초 이동 평균)·남은 시간(속도 기반 추정, "약")·현재 파일 | 탐색기 한 창 방식. 남은 시간은 추정치라 "약"을 붙이고 속도가 안정되기 전에는 보이지 않음 |
| 창 표시 시점 | 작업이 0.8초 넘게 걸리면 창을 띄움(포커스는 뺏지 않음). 자동으로 뜬 창은 대기열이 비면 닫힘. 메뉴로 연 창은 그대로 | 탐색기처럼 짧은 작업은 창이 깜박이지 않게 |
| 이름 충돌 | 실행 중 충돌을 만나면 묻는다: **건너뛰기(기본) / 둘 다 유지(번호 붙임) / 바꾸기** + "이 작업의 나머지 충돌에도 적용", `취소`는 작업 중지. 양쪽 종류·크기·수정 시각을 보이고 대상이 더 최신이면 ⚠ | 탐색기 3선택 + 비교 정보, TC "모두 …". 기본값은 대상을 바꾸지 않는 건너뛰기 |
| 바꾸기 방식 | 대상의 옛 항목을 **휴지통으로** 보낸 뒤 바꾼다. 복사는 먼저 임시 이름으로 다 복사하고 나서 옛 항목을 보내고 이름을 바꿔, 복사가 실패·취소되면 옛 항목이 그대로 남는다. 휴지통이 없는 위치(네트워크·이동식)는 바꾸지 않고 그 항목을 실패로 남긴다(대화상자에서 바꾸기 비활성) | 폴더 비교 창의 교체 규칙과 같음. 실행 취소로 옛 항목까지 되살릴 수 있게 |
| 폴더 충돌 | 폴더도 같은 세 선택. 바꾸기는 **대상 폴더 전체**를 휴지통으로(합치기 없음, 경고 표시) | 탐색기는 합치기를 하지만 합치면 안쪽 파일마다 덮어쓰기 기록이 필요해 실행 취소가 복잡해진다(사용자 확인 필요 결정 참고) |
| 같은 폴더에 복사 | 충돌로 묻지 않고 `이름 (2)`(기존 붙여넣기 동작) | 자기 자신과의 충돌이라 바꾸기가 의미 없음 |
| 오류 처리 | 항목 하나가 실패해도 다음 항목을 계속하고, 끝나면 실패만 모아 요약. 폴더 복사 안의 파일 하나가 실패하면 그 파일만 빼고 계속(요약에 표시). 폴더 **이동**은 안쪽 파일 하나라도 복사 못 하면 그 폴더를 되돌리고(복사본 삭제) 원본을 남김 | TeraCopy 방식(건너뛰고 계속, 끝에 요약). 이동은 원본을 지우므로 반쪽 상태를 남기지 않게 |
| 취소 | 진행 중이던 **최상위 항목 하나는 원래대로**(만들던 복사본·임시본 삭제, 바꾸려고 보낸 옛 항목 복원), 끝난 항목은 남고 기록됨 → 실행 취소로 되돌릴 수 있음 | "기록된 만큼만 되돌림" 요구. 항목 단위로 다 됐거나 안 됐거나만 남아 실행 취소가 단순하고 정확 |
| 끌어다 놓기 이동 | 대기열에 넣고 원본 쪽에는 `None`을 돌려줌(최적화 이동) | 셸 규약. 탐색기에서 끌어 온 이동을 탐색기가 지우지 않게 |
| 휴지통 없는 위치 삭제 | `Delete`(휴지통)로 고른 항목 중 휴지통에 보낼 수 없는 것(네트워크·이동식 드라이브, 260자 이상 긴 경로)이 있으면 **"되돌릴 수 없는 영구 삭제" 경고 + 확인 체크**를 받고 따로 영구 삭제 | 기존에는 확인 없이 영구 삭제됐다. AGENTS.md "되돌릴 수 없는 선택은 경고 + 확인 체크" |
| 실행 취소 범위 | 메인 패널의 복사·이동·휴지통 삭제·이름 변경·새 폴더·새 파일. 최근 작업부터(LIFO) 하나씩. 영구 삭제는 기록만 하고 건너뜀(확인 창에 "그 뒤 영구 삭제 n건은 되돌릴 수 없음" 표시) | 탐색기 범위와 같음. 링크 만들기·셸 우클릭 메뉴 작업·즐겨찾기 패널의 새 폴더는 범위 밖 |
| 실행 취소 확인 | `Ctrl+Z`는 **항상 확인 창**(무엇을 되돌리는지·언제 한 작업인지). 그 사이 바뀐 항목이 있으면 목록과 함께 "바뀐 항목은 그대로 두고 나머지만 되돌림" 체크를 해야 진행 | 탐색기(8 이후)는 묻지 않지만, 이 앱의 이력은 재시작 후에도 남아(7일) 오래된 작업을 모르고 되돌릴 수 있다. "결과가 바뀌었으면 확인 후 진행" 요구 |
| 복사 되돌리기 | 복사본을 **휴지통으로**(바꾸기였다면 옛 항목도 되살림). 휴지통이 없는 위치의 복사본은 되돌리지 않고 이유를 보임 | 원본이 그 사이 지워졌을 수 있어 영구 삭제는 위험 |
| 새 폴더·새 파일 되돌리기 | 폴더가 아직 비어 있고, 파일이 아직 0바이트·만든 시각 그대로일 때만 지움(비어 있으니 영구 삭제) | 그 사이 내용이 생겼으면 지우지 않음 |
| 진행 중 실행 취소 | 대기열에 작업이 있으면 실행 취소를 막고 안내 | 실행 중인 작업의 파일을 되돌리면 꼬임. 비교 창도 같은 규칙 |
| 실행 취소 실행 | 대기열 작업으로 백그라운드에서(큰 폴더를 다른 드라이브로 되돌려도 화면이 멈추지 않게). 중간에 취소하면 거기서 멈추고 다시 `Ctrl+Z`로 남은 항목을 이어서 되돌림 | 작업 이력의 기존 "도중에 멈추면 다시 부를 때 남은 항목만" 규칙 |

### 폴더 비교 창 이력과 공유할지

**분리**한다. 같은 `FileOperationJournal` 클래스를 쓰되 저장 폴더를 `%LOCALAPPDATA%\Folderss\file-history\`(메인 패널)로 따로 둔다.

- 비교 창의 작업 이력 패널은 그 창에서 한 작업만 보여 주고 "최근 작업 되돌리기"를 한다. 공유하면 비교 창의 되돌리기가 메인 패널 작업을, 메인 창 `Ctrl+Z`가 보이지 않는 비교 창 작업을 되돌리게 된다.
- 비교 창은 정적 `_journalBusy` 하나로 "한 번에 한 작업"을 지키고, 메인 대기열은 별도 작업 스레드다. 한 이력 객체·한 파일을 두 실행기가 같이 쓰면 순서·동시 쓰기를 맞추기 어렵다.
- 두 이력이 같은 파일을 건드려도 되돌리기는 매번 지금 상태(크기·수정 시각·자리 점유·휴지통에 있는지)를 확인하므로, 다른 쪽에서 바꾼 결과를 덮어쓰지 않는다.

## 구현 내용

### 대기열·실행기 (`Services/FileJobs.cs`, `Services/FileJobQueue.cs`, `Services/FileCopier.cs` — 순수 로직, 테스트에 링크)

- `FileJobQueue`: 작업 스레드 하나(셸 휴지통 때문에 STA)가 넣은 순서대로 실행. `Enqueue`·`ClearFinished`·`CancelAll`·`WhenIdleAsync`·`IsBusy`·`IsUndoRunning`, 이벤트 `JobsChanged`·`JobFinished`(작업 스레드), 충돌 질문 콜백 `AskConflict`. 끝난 작업은 30개까지 보관.
- 복사·이동: 먼저 파일 수·크기를 센다(같은 드라이브 이동은 제외). 파일은 `FileCopier.CopyFile`(Windows `CopyFileEx` + `COPY_FILE_FAIL_IF_EXISTS`, 진행 콜백에서 `FileJob.Checkpoint` → 일시정지 대기·취소 시 `PROGRESS_CANCEL`, 경로는 `\\?\`·`\\?\UNC\`로 긴 경로 허용). 폴더는 직접 걸으며 복사(깊이 256 제한, 숨김·시스템 폴더 속성 보존).
  - 같은 드라이브 이동은 `File.Move`/`Directory.Move`, 같은 루트인데 장치가 다르면(`ERROR_NOT_SAME_DEVICE`, 마운트 폴더) 복사 후 삭제로 전환. 다른 드라이브 이동은 복사 후 원본 삭제(읽기 전용 해제 후). 파일 원본을 못 지우면 복사본을 지워 이동 전으로, 폴더 원본 일부를 못 지우면 성공으로 기록하고 "양쪽에 남음"을 알림.
  - 같은 이름: `ConflictPolicy`(기본 건너뛰기, "나머지에도 적용" 기억). 같은 폴더에 복사는 묻지 않고 번호. 바꾸기는 휴지통에 보낼 수 있을 때만(`IRecycleBin.CanSend`) — 복사는 임시 이름(`~folderss-*.tmp`)으로 끝까지 복사한 뒤 옛 항목을 휴지통으로 보내고 이름을 바꾼다. 원본을 품은 상위 폴더는 바꾸지 않는다.
  - 실패·취소한 최상위 항목은 원래대로(만들던 복사본·임시본 삭제, 바꾸려고 보낸 옛 항목 복원). 폴더 복사 안의 파일 실패는 그 파일만 빼고 계속(오류 목록), 폴더 이동은 하나라도 실패하면 그 폴더를 되돌림.
- 삭제: 휴지통(`IRecycleBin.Send`, 보낼 수 없는 위치면 그 항목 실패 — 확인 단계에서 미리 나눔) 또는 영구 삭제(읽기 전용 해제 후).
- 이력: `FileOperationJournal.Begin` → 항목마다 `AddItem` → `End`(취소돼도 끝 기록, 끝난 항목만 기록됨). 이력을 쓰지 못하면 작업은 하고 "실행 취소할 수 없음"을 작업 메모로 남긴다. 이름 변경·새 폴더·새 파일은 `Rename`/`CreateFolder`/`CreateFile`이 바로 실행하고 기록(`_journalLock`).
- 실행 취소: `PeekUndo`(메뉴용, 파일 확인 없음), `PlanUndo`(항목별 되돌릴 단계와 막힌 이유, 중단된 작업 여부, 그 뒤 영구 삭제 수), `EnqueueUndo`(대기열 작업으로 `UndoAvailable` 실행, 취소하면 거기서 멈추고 다음 `Ctrl+Z`에 이어서), `SkipUndo`.
- `FileJob`: 상태(대기·준비·진행·일시정지·충돌 대기·완료·취소·실패), 항목·파일·바이트 수, `TransferRate`(최근 5초 이동 평균, 처음 1초는 남은 시간 없음), 오류·메모, `Snapshot()`. `FileJobFormat`: 바이트·속도·"약 4분 10초"·한 줄 설명.

### 작업 이력 확장 (`Services/FileOperationJournal.cs` — 추가만, 비교 창 동작 그대로)

- 종류 `Rename`·`CreateFolder`·`CreateFile`을 열거형 끝에 추가(저장은 이름).
- 외부 실행기용 `Begin`/`AddItem`/`End`/`MarkInterrupted`, 항목별 판정 `ItemProblems`(기존 `CheckUndo`는 이것을 모아 같은 문구), 막힌 항목은 두고 나머지만 되돌리는 `UndoAvailable`(막힌 것이 남으면 "넘김"으로 기록).
- 복사 되돌리기: 교체한 옛 항목이 있으면 휴지통에서 되살림(비교 창 복사는 교체가 없어 영향 없음). 복사본이 휴지통 없는 위치면 미리 막힘으로 판정(전에는 되돌리다 실패).
- `IRecycleBin.CanSend`(기본 구현 true — 테스트 가짜 휴지통 그대로 동작).

### 휴지통 (`Services/WindowsRecycleBin.cs`)

- `CanSend`/`IsRecyclable`: 고정 드라이브이고 260자 미만. `$I` 목록을 폴더 수정 시각 기준으로 다시 써서(항목이 들고 나면 다시 읽음) 항목 수만큼 휴지통 전체를 읽지 않게 함 — 1000개 삭제 되돌리기 확인이 멈추지 않게.

### 설계와 달라진 점

- 진행률 창은 도킹 패널이 아닌 별도 창: 도킹 레이아웃 저장·복원(`ResolveDockContent` 등)을 건드리지 않고, 다른 작업과 병합 충돌을 줄이기 위해.
- ⋯ 메뉴에 `반대편 패널로 복사/이동`을 더함: 복사를 시작할 메뉴가 없어(`Copy_Click`이 어디에도 연결되지 않음) 진행률을 메뉴에서 쓸 수 없었고, UIA로 실제 실행 확인에도 필요했다.
- 탐색기 끌어다 놓기 이동의 반환값을 `Move` → `None`으로 바꿈(조사 결과 셸 규약).

## 알려진 한계

- 실행 취소 범위 밖: 링크 만들기, 바로 가기(.lnk) 놓기, Windows 셸 우클릭 메뉴로 한 작업, 즐겨찾기 패널의 새 폴더·새 파일, 뷰어에서 한 파일 편집.
- 복사 되돌리기는 복사본을 휴지통으로 보낸다 — 휴지통이 없는 위치(네트워크·이동식)의 복사본은 되돌리지 않고 이유를 보인다(직접 지워야 함).
- 휴지통 크기 제한을 넘는 큰 항목은 셸이 확인 없이 영구 삭제할 수 있고, 그러면 되돌리기 확인에서 "휴지통에 없음"으로 막힌다(보낼 때는 알 수 없음).
- 폴더 복사는 ACL·폴더 수정 시각을 옮기지 않는다(파일은 `CopyFileEx`가 속성·수정 시각·대체 데이터 스트림 보존). 예전 `CopyDirectory`와 같다.
- 링크 폴더(junction·심볼릭)는 예전처럼 따라 들어가 내용을 복사한다(순환은 깊이 256에서 오류).
- 끌어다 놓기는 UIA로 흉내 낼 수 없어 실제 실행 확인을 하지 못했다(같은 `QueueFileTransfer` 경로).
- 진행률 창이 자동으로 닫히는 순간 메인 메뉴를 열면 메뉴가 닫힐 수 있다(자동 확인에서 메뉴 항목을 한 번 못 찾은 원인으로 추정, 메뉴를 다시 열면 됨).
