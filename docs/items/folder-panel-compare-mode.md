# 좌우 폴더 패널 비교 모드

- 상태: Todo

## 요구사항

- 좌우에 배치한 두 폴더 패널에서 바로 폴더를 비교한다. 별도 창이 아니라 각 패널 목록 위에 비교 상태(같음·다름·이쪽만·저쪽만·유형 다름)를 겹쳐 보인다.
- 비교 중에도 패널의 기존 동작(반대편 복사·`F6` 이동·삭제·열기·드래그)을 그대로 쓴다.
- 한쪽에서 하위 폴더로 이동하면 반대쪽도 같은 상대 경로로 따라간다.
- 2026-10-15 사용자 확인 중 요청: 전용 비교 창(`directory-compare.md`)을 써 본 뒤 "폴더 패널을 좌우 두 개 배치해서 비교하는 방식이 좋다"며 다음 아이템으로 기록.

## 원인 분석 또는 설계

- 처음 상세설계(패널 오버레이 방식)가 이미 있다: 커밋 `195295f`의 `docs/items/directory-compare.md`
  (`git show 195295f:docs/items/directory-compare.md`). UI 설계, 동기 이동, 자리표시자 행, 테마 색, 리스크를 그대로 출발점으로 쓴다.
- 전용 비교 창에서 만든 것을 재사용한다.
  - 판정: `DirectoryCompareService`, `DirectoryCompareOptions`, `CompareSettingsService` (옵션 공유 — 창과 패널이 같은 `compare-settings.xml`).
  - 옵션 대화상자: `DirectoryCompareOptionsDialog`, `▾` 공용 스타일 `OptionArrowButton`.
  - 상태 표시 문구·색: `DirectoryCompareView.Row`의 상태 문구·배지 색을 공용으로 빼서 패널 비교 컬럼과 같이 쓴다.
- 처음 설계와 달라질 점(착수 시 결정): 서비스 결과는 비교 루트 전체를 한 번에 판정한 목록이므로, 패널은 현재 폴더 상대 경로의 직속 항목만 골라 입힌다.
  자리표시자 행의 복사·삭제 경로 누수, 동기 이동 핑퐁, 트리뷰 고정과의 상호작용이 주요 회귀 위험이다(처음 설계의 리스크 절).
- 전용 비교 창은 유지한다(패널 배치와 무관하게 아무 두 폴더나 비교). 패널 비교 모드에서 창으로 넘기는 버튼을 둘지 결정한다.
