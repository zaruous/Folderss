# Git 창: 워킹트리(저장소) 전환 중 상태 메시지

- 상태: Ready for Verification

## 요구사항

Git 창에서 워킹트리 전환이 느리므로, 워킹트리를 고른 상태에서 다른 항목(브랜치)을 눌러 전환되는 동안 상태 메시지로 진행을 안내한다.

## 원인 분석 또는 설계

- 저장소 목록에서 다른 저장소·워킹트리를 고르면(`RepoList_SelectionChanged` → `ReloadSelectedDetailAsync`) 브랜치·로그·브랜치 그래프·원격 비교·
  워킹트리 목록·stash를 차례로 읽는데, 이 경로는 `RunBusyAsync`를 거치지 않아 상태 줄이 `저장소 N개` 그대로였다.
- 링크된 워킹트리는 LibGit2Sharp가 지원하지 않아 모든 조회가 git CLI로 돌아가므로 이 구간이 특히 느리다.
- 해석: "다른 브랜치 클릭"은 저장소 목록에서 다른 워킹트리(각자 다른 브랜치) 행을 누르는 것으로 보았다.
  브랜치 탭의 `브랜치 전환`(git switch)은 이미 `RunBusyAsync`로 "브랜치 전환 중…"이 끝날 때까지 보인다.

## 구현 내용

- `ShowDetailLoadingStatus(row, 단계)`: `"<경로> [<브랜치>] 불러오는 중… <단계>"`. 단계: 브랜치·로그 → 브랜치 그래프(브랜치 탭일 때) → 원격 비교 → 워킹트리 목록 → stash.
- `EndDetailLoadingStatus(row)`: 끝나면(오류·취소 포함) `저장소 N개`로 되돌린다.
- 다른 작업(`RunBusyAsync`) 중이면 그 상태를 덮지 않고, 읽는 사이 다른 저장소를 골랐으면 옛 저장소의 단계를 표시하지 않는다.
  `LoadBranchesAndLogAsync`는 명령 실행 후 다시 읽기에서도 쓰이지만 그때는 작업 중이라 표시하지 않는다.

## 검증

- Linux에서 `ConsolePanel` 한 줄(Windows 전용 패키지)만 막은 복사본으로 C# 컴파일 성공. **Windows 빌드 확인 필요.**
- 앱에서 확인 필요: 워킹트리가 여러 개인 저장소에서 워킹트리 행을 바꿔 고를 때 상태 줄에 단계가 바뀌며 보이는지, 끝나면 `저장소 N개`로 돌아오는지,
  빠르게 연달아 바꿔 고를 때 마지막에 고른 저장소 이름만 보이는지, 명령 실행 중에는 그 명령의 상태가 유지되는지.
