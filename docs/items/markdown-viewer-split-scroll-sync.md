# 마크다운 분할(Split) 보기 스크롤 동기화

- 상태: Done

## 요구사항

Split 모드에서 편집기나 미리보기 한쪽을 스크롤하면 다른 쪽도 비슷한 위치로 따라와야 한다.

## 원인 분석 또는 설계

- 편집기와 미리보기가 따로 스크롤돼, 긴 문서에서 편집 중인 부분의 결과를 찾으려면 미리보기를 직접 내려야 했다.
- 편집기는 `<textarea>`를 유지하기로 했으므로(Monaco 교체 안 함) 원문 줄과 렌더링 블록을 잇는 정밀 매핑 대신 스크롤 비율로 맞춘다.
- 한쪽을 맞추면 상대편에서도 scroll 이벤트가 나 서로 끌어당기므로, 150ms 동안은 먼저 움직인 쪽만 기준으로 삼는다.
- 입력 중 미리보기를 다시 그리면 높이가 바뀌며 미리보기 scroll 이벤트가 나 편집기가 튈 수 있어, 다시 그릴 때는 편집기를 기준으로 고정한다.

## 구현 내용

- `markdown-app.html`
  - `syncSplitScroll(from, to)`: Split 모드에서만, `from`의 스크롤 비율을 `to`에 적용. `_scrollDriver`로 되돌림 방지.
  - 편집기·미리보기 `scroll` 이벤트에서 호출.
  - `renderPreview`: Split이면 다시 그리기 전에 `_scrollDriver = editor`로 고정.

## 검증

- 헤드리스 Edge: 400줄 문서 Split 모드에서 편집기를 절반 위치로 스크롤 → 미리보기 비율 0.5. Preview 모드에서는 미리보기 스크롤이 편집기를 움직이지 않음.
- 앱에서 확인 필요: 실제 스크롤 휠·스크롤바 드래그, Split에서 입력할 때 편집기가 튀지 않는지.
- 알려진 제약: 비율 기준이라 큰 이미지·다이어그램·표가 많은 문서에서는 위치가 정확히 맞지 않는다.
