# 화면 영역 캡쳐 (⋯ 메뉴 > 화면 캡쳐…)

- 상태: Ready for Verification

## 요구사항

- ⋯ 메뉴의 `테마` 아래에 캡쳐 도구를 둔다.
- 픽픽 등 캡쳐 도구처럼 반투명 바탕 위에서 마우스로 영역을 지정해 캡쳐하고, 결과를 팝업으로 보여 준다.
- 2단계: 결과 위에 도형·텍스트 넣기, 캡쳐된 영역 자르기, 이미지 리사이즈 후 저장.

## 원인 분석 또는 설계

사용자와 합의한 기본값(1단계):

- **정지 화면 방식**: 메뉴를 누르면 가상 화면 전체를 먼저 찍고, 그 그림을 모든 모니터를 덮는 오버레이 창에 깔아 그 위에서 고른다. 오버레이 자신이 찍히지 않고, 고르는 동안 화면이 바뀌어도 누른 순간의 모습이 남는다.
- **Folderss 창 숨김**: 찍기 전에 본체 창을 `Hide()`하고 300ms 기다린다(⋯ 메뉴 닫힘·DWM 숨김 페이드). 그래서 Folderss 자신은 찍을 수 없다.
- **저장**: (아래 "캡쳐 설정"에서 기본 저장 폴더로 바뀜) `저장` 버튼은 활성 폴더 패널에 `캡쳐_yyyyMMdd_HHmmss.png`(같은 이름이 있으면 `_2`…)로 바로 저장하고, 옆 `▾`는 다른 이름으로 저장(PNG/JPEG/BMP, 확장자로 형식 결정, 그 밖의 확장자는 거부). 활성 폴더가 고정(📌)이면 새 파일과 같은 규칙으로 막는다.
- **클립보드**: 결과 창이 열리면 자동 복사. 실패는 `ClipboardService`가 알린다.
- **단축키 없음**: 메뉴만. 전역 핫키는 다른 프로그램과 충돌 문제가 있어 별도 작업.

DPI·멀티모니터:

- 앱은 시스템 DPI 모드(매니페스트 없음)다. `SystemInformation.VirtualScreen`(픽셀)과 `SystemParameters.VirtualScreen*`(DIP)은 같은 DPI 문맥의 값이라 서로 맞는다. 왼쪽·위쪽 모니터는 음수 좌표.
- 자르는 위치는 화면 좌표가 아니라 오버레이에 늘려 그린 그림 기준 비율(`ScreenCaptureService.ToPixelRect`)이라, 창이 실제 화면과 조금 어긋나도 사용자가 본 그림 그대로 잘린다.
- 알려진 제약: 배율이 다른 보조 모니터는 시스템 DPI 앱에 대해 Windows가 가상화한 해상도로 찍혀 흐릿할 수 있다. 앱 전체를 PerMonitorV2로 바꾸는 것은 AvalonDock·WebView2 전체에 영향이 커 캡쳐 때문에 하지 않았다.

2단계 편집(합의 없이 정한 기본값, 사용자 확인 대상):

- 도구는 사각형·타원·화살표·텍스트·자르기 + 크기 조절·되돌리기. 다시 실행, 자유 곡선은 요청 밖이라 넣지 않음. 선택은 아래 2단계 보완에서 추가.
- 기본 도구는 없음(보기만) — 결과 창을 열자마자 클릭으로 도형이 그려지는 사고 방지. 같은 도구를 다시 누르면 꺼짐.
- 도형·텍스트는 저장 전까지 이미지와 분리된 값이고, 저장·복사 때만 `RenderTargetBitmap`으로 합친다. (2단계 보완 전에는 자르기·크기 조절 때도 합쳤다.)
- 되돌리기 스냅숏은 (이미지 참조, 도형 배열)이라 도형 편집은 가볍지만, 자르기·크기 조절마다 이미지가 한 장씩 쌓인다. 횟수 제한은 두지 않았다.
- 좌표는 이미지 픽셀 단위(편집면 DIP = 픽셀), 화면에는 캡쳐 DPI만큼 줄여 1:1 픽셀로 보임. 글자 크기·굵기도 픽셀 단위.
- 자르기는 드래그를 놓으면 바로 적용(되돌리기 가능). 크기 조절은 대화상자(비율 유지 기본 켬, 한 변 최대 16384).
- 편집 후 저장·복사 없이 닫으면 확인한다. 복사도 "보관함"으로 본다.
- JPEG 저장은 합친 이미지(Pbgra32)를 24비트로 변환해 넘긴다(JPEG 인코더는 알파 형식을 받지 않음).

2단계 보완: 선택·이동·크기 변경(사용자 요청 "도형을 선택하고 크기 조절하는 기능이 없다", 제안 범위 승인):

- `↖ 선택` 도구: 도형을 눌러 선택하면 점선 상자와 핸들이 보인다. 끌어서 이동, 핸들로 크기 변경, Delete로 삭제. 사각형·타원은 핸들 8개, 화살표는 양 끝 2개, 텍스트는 이동만(글자 크기 변경·내용 재편집은 범위 밖).
- 되돌리기 구조 변경: 도형을 화면 요소로 기록하면 제자리 이동이 과거 기록까지 바꾼다. 도형을 불변 값(`CaptureAnnotation`)으로 바꾸고 화면 요소는 값에서 매번 다시 만든다.
- 자르기·크기 조절은 도형을 합치지 않는다: 자르기는 도형을 자른 원점만큼 옮기고, 크기 조절은 같은 배율로 늘린다(굵기·글자 크기는 가로·세로 배율의 기하 평균). 그래서 그 뒤에도 도형을 고칠 수 있다. 자른 영역 밖으로 나간 도형도 지우지 않고 남겨 둔다(보이지 않음).
- 선택 판정: 상자형(사각형·타원·텍스트)은 테두리 상자 안이면 잡힌다(속이 빈 도형을 선 위만 눌러야 하는 불편 방지). 화살표는 선에서의 거리. 겹치면 나중에 그린 도형이 먼저 잡힌다 — 큰 사각형 안의 작은 도형은 잡히지만, 작은 도형 아래의 큰 도형은 겹친 부분 밖을 눌러야 한다.
- 핸들 크기(8)·집기 여유(6)는 화면 DIP 기준이라 배율이 달라도 같은 크기로 보이고 잡힌다.
- 이미지 모서리 끌기로 크기 조절은 넣지 않고 `크기 조절…` 대화상자를 유지.
- 결과 창 최대화(사용자 요청): 처음 크기는 작업 영역 85% 이내로 내용에 맞추고, 첫 표시 뒤에는 그 크기로 고정한 채 최대 크기 제한을 푼다(WPF는 최대화도 MaxWidth/MaxHeight에 묶음). 그래서 자르기·크기 조절 뒤 창이 내용 크기를 따라 줄거나 늘지 않는다.
- 선택한 도형의 색·굵기를 바꾸는 기능은 이번 범위가 아니다(색·굵기 선택은 새로 그리는 도형에만 적용).

3단계: 흰 페이지 + 캡쳐 이미지 오브젝트(사용자 요청 "팝업 배경을 페이지처럼 흰 바탕으로, 캡쳐본도 오브젝트처럼 선택·크기 조절"):

- 편집면은 흰 페이지(`Canvas.Background = White`)이고 캡쳐 이미지는 그 위의 오브젝트다. 이미지 자리는 `CaptureAnnotationKind.Image` 값으로 도형 배열 [0]에 두고(비트맵은 편집면이 하나로 고정), 선택·이동·핸들 끌기·자르기·크기 조절 코드를 도형과 그대로 공유한다. 항상 [0]이라 맨 아래에 그려지고, 겹친 곳은 도형이 먼저 잡힌다. 이미지는 Delete로 지우지 않는다.
- **페이지 크기는 처음에 캡쳐 크기와 같고 이미지가 꽉 찬다**(합의 없이 정한 기본값). 그래서 아무것도 바꾸지 않으면 저장·자동 복사 결과가 캡쳐 원본 그대로다 — 페이지를 캡쳐보다 크게 두면 열자마자 복사되는 그림에 흰 여백이 붙으므로 그렇게 하지 않았다. 흰 바탕은 이미지를 줄이거나 옮긴 뒤 드러난다.
- 이미지 핸들: 모서리 4개는 비율 유지(반대편 모서리 고정, 가로·세로 중 더 많이 끈 쪽에 맞춤), 변 4개는 그 방향으로만 늘림(의도적 변형). 반대편을 넘기면 고정점 너머에 놓이고 거울 반전은 없다.
- 자르기는 페이지만 줄이고 이미지·도형을 자른 원점만큼 옮긴다. `크기 조절…`은 페이지와 이미지·도형을 같은 배율로 늘린다(이전과 같은 의미: 결과 크기 변경). 둘 다 비트맵을 다시 샘플링하지 않으므로 되돌리기 스냅숏이 (페이지 크기, 도형 배열)만 남고 메모리가 줄었다. 늘리거나 줄인 이미지는 `BitmapScalingMode.HighQuality`로, 캡쳐 크기 그대로면 `NearestNeighbor`로 그린다.
- 저장·복사: 페이지 = 캡쳐 크기, 이미지가 (0,0)에 꽉 차고 도형이 없으면 캡쳐 원본을 그대로 내보낸다(DPI 포함). 그 밖에는 페이지를 `RenderTargetBitmap`(96 DPI)으로 합친다 — 흰 바탕이 들어간다.
- 결과 창은 페이지 둘레에 테마 `BorderBrush` 1픽셀 테두리를 둬 밝은 테마에서도 페이지 경계가 보이게 한다(내보내지 않음).
- 페이지만 키우기(이미지는 그대로 두고 흰 여백 추가)는 이번 범위에 넣지 않았다. → 3단계 보완에서 `배경 크기…`로 추가.

3단계 보완: 초기 흰 배경 = 팝업 전체, 배경 크기 옵션(사용자 요청):

- (아래 "초기 흰 배경 = 디스플레이 해상도"로 대체됨) 처음 열 때 흰 배경을 결과 창의 보이는 영역(스크롤 영역 − 페이지 여백·테두리)만큼 넓힌다. 창 크기 규칙(내용에 맞춤, 최대 작업 영역 85%)은 그대로다. 창 너비는 도구 줄을 한 줄로 펼친 너비(약 1000px)로 정해지므로 작은 캡쳐는 오른쪽에 흰 배경이 넓게 생긴다(이전 기록의 "640 너비로 열림"은 틀린 설명이었다 — 640은 최소값일 뿐). 캡쳐가 보이는 영역보다 크면 그 변은 캡쳐 크기(이미지가 잘리지 않게). 이미지는 왼쪽 위(0,0) 그대로.
- 넓히는 시점은 `ContentRendered`(창 크기 확정 뒤)다. 이 넓힘은 되돌리기·미저장 표시를 남기지 않는다(열린 상태로 봄).
- **자동 복사와 저장 결과가 다르다**: 열자마자 하는 자동 복사(`Loaded`)는 넓히기 전이라 캡쳐 그대로이고, 그 뒤 `복사`·`저장`은 흰 배경까지 포함한다. 캡쳐만 남기려면 `배경 크기…`로 캡쳐 크기를 넣거나 자르기를 쓴다.
- 창 크기를 나중에 바꾸거나 최대화해도 흰 배경은 따라가지 않는다(처음 한 번만).
- 계산은 `ScreenCaptureService.InitialPageSide`(화면 DIP ÷ 표시 배율, 내림, 캡쳐 이상, 한 변 최대 이하).

초기 흰 배경 = 디스플레이 해상도(사용자 요청 "흰 배경이 팝업 크기에 비례해 보인다, 디스플레이 최대 크기에 비례하게"):

- 처음 흰 배경 = 결과 창이 뜨는 모니터의 해상도(`Screen.FromHandle(소유자 창).Bounds`, 픽셀). 작업 표시줄을 뺀 작업 영역이 아니라 모니터 전체다. 결과 창은 소유자(본체 창) 가운데에 뜨므로 소유자가 있는 모니터를 쓴다. 캡쳐가 더 크면(여러 모니터에 걸친 캡쳐) 그 변은 캡쳐 크기.
- 좌표계: 앱은 시스템 DPI라 `Screen.Bounds`와 캡쳐(GDI) 픽셀이 같은 문맥이다. 배율이 시스템과 다른 보조 모니터는 Windows가 가상화한 크기로 나올 수 있다(캡쳐와 같은 알려진 제약).
- 넓히는 시점을 `ContentRendered`에서 `SourceInitialized`로 옮겼다: 창 크기를 내용에 맞춰 정하기 전에 넓혀야 창이 넓힌 페이지에 맞춰 열린다. 그래서 **결과 창은 캡쳐 크기와 관계없이 거의 항상 작업 영역의 85% 크기로 열린다**(페이지가 해상도 크기라 85% 제한에 걸림). 이전처럼 작은 창을 원하면 이 시점을 되돌리면 된다.
- **저장·복사 결과 크기**: 아무것도 하지 않고 `저장`하면 모니터 해상도 크기(예: 1920×1080)의 흰 그림 위에 캡쳐가 왼쪽 위에 놓인다. 캡쳐만 남기려면 자르기나 `배경 크기…`를 쓴다. 열자마자 하는 자동 복사는 넓힌 뒤에 일어나므로, 명시적으로 캡쳐 원본(`Copy(image)`)을 복사하게 바꿨다. `복사` 버튼은 페이지 전체.
- `배경 크기…`: 기존 `CaptureResizeDialog`를 제목·비율 유지 기본(끔)·안내문만 바꿔 재사용. 이미지·도형은 그대로 두고 페이지만 바꾼다(왼쪽 위 기준, 되돌리기 가능). 줄여서 밖으로 나간 부분은 저장되지 않지만 지워지지는 않는다.
- "옵션"을 결과 창의 `배경 크기…` 대화상자로 해석했다. 설정 창에 "처음 배경 크기(팝업 전체/캡쳐 크기/고정값)" 기본값을 두는 것은 넣지 않았다.

저장 폴더 열기(사용자 요청 "▽ 기본 저장 폴더 열기, 저장 완료 후 열어보겠냐는 대화상자"):

- `▾`는 바로 다른 이름으로 저장하던 버튼에서 메뉴로 바뀌었다: `다른 이름으로 저장… (PNG / JPEG / BMP)`, `기본 저장 폴더 열기`. 다른 이름으로 저장은 한 번 더 눌러야 한다.
- (아래 "캡쳐 설정"에서 설정 폴더로 바뀜) 기본 저장 폴더 = `저장`이 쓰는 폴더 = 누른 시점의 활성 폴더 패널. Folderss 패널은 이미 그 폴더를 보고 있으므로 Windows 탐색기로 연다. 열기만 하므로 고정(📌) 폴더도 연다(저장은 여전히 막힘).
- 저장(빠른 저장·다른 이름 모두)이 끝나면 "저장한 위치를 탐색기에서 열까요?"를 묻고, 예면 탐색기에서 저장한 파일을 선택한 채(`/select`) 연다. 기본 버튼은 아니오(Enter로 바로 넘김). "다시 묻지 않기"·설정 창 기본값은 넣지 않았다 — 매번 묻는 것이 번거로우면 추가 대상.
- 탐색기 실행 실패는 결과 창을 소유자로 한 메시지로 알린다.

결과 창 레이아웃 정리(사용자 요청 "컨트롤 높이·너비·배치 확인, UX 고도화"; 실행 화면을 찍을 수 없어 스타일 값으로 계산하고 HTML 모형으로 비교):

- 발견한 문제: ① `▾`만 위아래 여백을 0으로 덮어써 `저장`보다 약 6px 컸다. ② 도구 줄 컨트롤 높이가 25(토글)·28(색)·23(버튼)으로 달랐다. ③ 줄바꿈 패널에 낱개로 넣어 좁히면 색 팔레트 중간에서 끊기고 구분선이 줄 끝·앞에 남았다. ④ 상태 문구가 저장 줄에 끼어 경로가 잘렸다. ⑤ 도구 줄과 페이지 영역 사이에 구분이 없었다.
- 배치: 명령 줄(저장·▾·복사 | 되돌리기 ··· 닫기) / 도구 줄(도구 · 색·굵기·글자 · 크기 조절·배경 크기 세 묶음, 묶음 단위로 접힘) / 페이지(사방 12 여백) / 상태 줄(상태 문구 ··· 페이지 크기 px). 명령·도구·상태 줄은 `SurfaceBackground` 면과 구분선으로 페이지와 나눈다.
- 되돌리기를 명령 줄로 옮겼다: 도구 줄이 접혀도 항상 같은 자리에 보이게.
- 모든 도구 줄 컨트롤 높이 28(`ControlHeight`), 기본 버튼 스타일의 여백 3·안쪽 12,7은 `Compact`로 덮어씀. `▾`는 저장과 테두리를 1픽셀 겹쳐 분할 버튼처럼 보이게.
- 최소 높이 200 → 400: 흰 페이지를 작업 공간으로 쓰므로 작은 캡쳐도 위아래 여유를 둔다.
- 단축키(도구 전환), 확대/축소, 아이콘 교체는 요청 밖이라 넣지 않았다.

캡쳐 설정(사용자 요청 "캡쳐 설정을 추가해 기본 저장 경로는 사용자 디렉토리, 바꿀 수 있게"):

- 설정 창 왼쪽 목록에 `캡쳐`(비교 다음, 플러그인 앞)를 추가했다. 요청의 "플러그인의 캡쳐 설정"은 설정 창 항목으로 해석했다(캡쳐는 플러그인이 아니라 본체 기능).
- 기본 저장 폴더: 기본값은 사진 폴더(`Environment.SpecialFolder.MyPictures`, 예 `C:\Users\이름\Pictures`. OneDrive 등으로 옮겼으면 옮긴 곳). 사진 폴더 경로를 얻지 못하면 사용자 폴더. 처음에는 사용자 폴더였다가 사용자 요청으로 바꿈. `찾아보기…`(폴더 선택), `기본값`(사진 폴더로 되돌림). 비워 두고 저장하면 기본값. 저장 시 드라이브부터 쓴 전체 경로이면서 있는 폴더만 받는다(저장할 때 가서야 실패하지 않게). 환경 변수(`%USERPROFILE%`)는 풀지 않는다.
- **동작 변경**: `저장`은 이제 활성 폴더 패널이 아니라 이 폴더에 저장한다. `▾ > 기본 저장 폴더 열기`도 이 폴더를 연다. 활성 폴더 패널에 저장하던 이전 동작은 선택지로 남기지 않았다(요청 밖). 저장 폴더를 활성 패널이 보고 있으면 이전처럼 패널을 새로 고치고 파일을 선택한다.
- 저장·열기 때마다 설정 파일을 다시 읽으므로 결과 창을 열어 둔 채 설정을 바꿔도 반영된다. 설정 폴더가 지워졌으면 저장 때 알리고 설정 > 캡쳐 또는 다른 이름으로 저장을 안내한다. 고정(📌) 검사는 그대로.
- `CaptureSettingsService`(capture-settings.xml, `SettingsFile.Write`, 읽기 실패는 기본값, 쓰기 실패는 예외 → 설정 창 `설정 저장 실패`).
