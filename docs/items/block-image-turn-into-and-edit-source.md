# 블록 편집기: 전환 > 이미지, 이미지 주소 편집

- 상태: Ready for Verification — 단위 테스트 통과, Windows 빌드·실제 창 확인 대기
- 시작일: 2026-11-09

## 요구사항

1. URL을 붙여넣은 블록을 블록 메뉴 `전환 > 이미지`로 이미지 블록으로 바꾸고 싶은데 메뉴에 `이미지`가 없다.
2. 이미지 블록을 넣은 뒤 이미지 주소를 고치는 기능.

## 원인

- `전환` 하위 메뉴는 `/` 명령 중 블록 종류(`Kind`)가 정해진 것만 넣는다(`BlockEditor.cs` 블록 메뉴). 이미지·북마크·파일 첨부·페이지는 "경로를 묻고 새 블록을 넣는" 동작(`Run`)뿐이라 빠진다.
- 이미지 블록은 편집 상태에서 위쪽에 경로 입력란(`_metaBox`)이 나타나지만 테두리·배경 없는 작은 회색 글자라 고칠 수 있는 칸으로 보이지 않고, 메뉴에도 없다.

## 구현

- `Services/BlockMarkdown.ImageSourceOf(text, isImageFile)` — 한 줄이고, http·https·file 주소(확장자 무관 — 이미지 URL은 확장자가 없을 때가 많다) 또는 이미지 파일 경로(공백 허용)일 때 그 경로. `<주소>` 자동 링크 표기는 벗긴다.
- `BlockEditor` 블록 메뉴: `전환` 끝에 `이미지` — 고른 블록이 모두 서식 글 블록이고 `ImageSourceOf`가 경로를 돌려줄 때만 켬(꺼져 있으면 툴팁으로 조건 안내). 글을 `Source`로 옮기고 대체 텍스트는 비움, 실행 취소 한 단계(`TurnIntoImage`).
- 이미지 블록 메뉴 `이미지 주소 편집` — 블록 선택을 풀고 기존 경로 입력란에 커서·전체 선택(`FocusMeta`, 메뉴가 닫힌 뒤). 고치면 기존 `OnMetaChanged`가 다시 그리고 실행 취소 기록.

## 결정

- 아무 글이나 이미지로 바꾸면 깨진 블록이 되므로 조건에 맞지 않으면 메뉴를 끈다(숨기지 않음 — 기능이 있음을 알 수 있게).
- 북마크·파일 첨부·페이지 전환은 요청 범위 밖이라 넣지 않음.
- 원격 이미지는 기존 정책대로 블록 안 `이번만 불러오기`를 눌러야 보인다.

## 검증

- [x] `BlockImageTurnIntoTests` 11개 통과(허용 5: https·확장자 없는 URL·`<URL>`·상대 경로·공백 있는 로컬 경로, 거부 6: 빈 글·문장·이미지 아닌 파일·URL 뒤 글·두 줄·ftp)
- [x] Linux `EnableWindowsTargeting` 빌드: 기존 `ConsolePanel` 오류 1건만
- [ ] 실제 확인: URL 붙여넣기 → 블록 메뉴 `전환 > 이미지` → 이미지 블록, `Ctrl+Z`로 되돌림. 일반 문장 블록에서는 `이미지`가 꺼져 있고 툴팁. 이미지 블록 메뉴 `이미지 주소 편집` → 경로 입력란 전체 선택, 고치면 바로 다시 그림.

## 관련 보고 (미해결)

- `/이미지`로 넣은 뒤 툴바 `미리보기`로 전환하면 COMException(0x8007130F, "그룹 또는 리소스가 요청된 작업을 실행할 올바른 상태에 있지 않습니다")으로 페이지 전체가 표시되지 않음.
  코드로는 원인을 확정하지 못함: 빈 경로는 `![]()`로 저장되고 페이지의 `<img src="">`는 요청을 보내지 않으며, Markdown·Monaco 뷰어의 WebView2 환경 옵션은 같다.
  재현 단계(경로를 채웠는지, 오류가 뜬 위치)와 오류 전문을 받아 따로 처리한다.
